# Playtest Session — 2026-10-17 (v2.1.0 Windows portable L0 acceptance)

L0 acceptance of the **published** v2.1.0 Windows build
([release](https://github.com/SwiggitySwerve/MekStation/releases/tag/v2.1.0), 18 assets, unsigned).
Goal: prove the shipped portable executable works end to end on Windows —
launch, embedded server, window, customizer, save/reload, record sheet,
tactical battle to completion, Results, second battle, exit.

**Verdict: FAIL (release-blocking for desktop users).** The embedded server and
the full product loop work, but the packaged Electron window never loads the UI
on Windows (2/2 launches): the user sees a "Startup Error" dialog and a blank
window with no reload path. The core loop was therefore driven through a browser
pointed at the app's own embedded server. Fixes route as v2.1.x.

## Observations (not filed as defects)

- **BV parity to verify:** the unmodified canonical HBK-4G showed BV **1,077** in the customizer, while the Quick Game demo list shows HBK-4G at **1,067** (the commonly published value). The edited design (no Small Laser) also computes 1,067. Needs a parity check against the canonical reference before filing.
- Server stderr on every start: `Yjs was already imported. This breaks constructor checks` and Node `DEP0169 url.parse()` deprecation.
- Missing `dist/assets/icons/icon.ico` inside `app.asar` (`Failed to load image from path …icon.ico`), so the window and tray use default icons.
- Portable cold start is ~65–70 s of self-extraction before any UI appears, with no splash.
- The spectator battle (stage 13) is neither listed in Games nor stored under `/api/matches`. That may be intentional for spectator mode.
- Two `404` resource errors in the browser console when the record-sheet preview first renders (URLs not retained by the resource timing buffer).
