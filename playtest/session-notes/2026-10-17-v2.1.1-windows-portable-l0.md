# Playtest Session — 2026-10-17 (v2.1.1 Windows portable L0 re-run)

L0 acceptance re-run of the **published** v2.1.1 Windows build
([release](https://github.com/SwiggitySwerve/MekStation/releases/tag/v2.1.1), 18 assets, unsigned),
following the v2.1.0 FAIL in
[`2026-10-17-v2.1.0-windows-portable-l0.md`](./2026-10-17-v2.1.0-windows-portable-l0.md).
v2.1.1 carries #2210 (desktop startup/preload/updater/quit), #2211 (0-MP lock-in,
kill dedupe, engine crit layout, fog strip) and #2209 (mojibake, unit detail page,
games labels, log names). This time the whole loop was driven **inside the packaged
Electron window** (CDP on `--remote-debugging-port=9333`, Playwright
`chromium.connectOverCDP`), not in a browser.

**Verdict: PASS with defects (not release-blocking).** The desktop window loads the
dashboard on every launch (4/4), the preload bridge and updater work, and the full
loop (customizer → save → restart → record sheet/PDF → battle → Results → reload →
second battle → unit detail → exit) completes in the app window. Closing the window
removes every MekStation process and frees the ports. L0-01, L0-02, L0-03, L0-08,
L0-09 and L0-10 are fixed. L0-04 is fixed for the stationary 0 MP path. L0-07 and
L0-11 are only partly fixed. Two new P1/P2 gameplay defects were found: AI hex
stacking (V211-01) and prone units silently skipped (V211-03). Neither blocks the
loop, but both should be fixed in v2.1.2.

## Observations (not filed as defects)

- Main stderr: `System tray unavailable: Error: Failed to load image from path …app.asar\dist\assets\icons\tray.ico` (tray icon asset missing). The v2.1.0 `icon.ico` error is gone.
- Server stderr is unchanged: `Yjs was already imported…` and Node `DEP0169 url.parse()`.
- Battle 1 `retreat_triggered` names edge `south`, but the WVR exits at `r=-14` (top of the map). Check the edge naming against the map orientation.
- The unit detail page lists quad/tripod leg armor rows (all 0) for a biped.
- While a map hover tooltip is open, the movement budget buttons switch between two layouts (measured box alternates 740,554 ↔ 16,665), so automated clicks fail with "element is not stable". Moving the pointer off the map stabilizes them. This may show as flicker to users.
- PDF export in Electron has no `will-download` handler. Users get Chromium's default save prompt (not exercised here because CDP captured the download).
- Interactive AI vs the slow HBK tends to kite or retreat, so neither interactive battle ended by destruction. L0-05 still needs a regression check from a destruction-ending interactive match.
