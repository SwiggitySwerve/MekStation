## Operator policy and open OB-2 clause

For this single-operator topology, the operator has full administrative access to every local record; there is no per-campaign ownership column. Secret provisioning is environment or a protected data-directory file (0600 on POSIX, restrictive user ACL on Windows). The local session route checks proof, explicit Origin and CSRF/replay/expiry rules and issues a bounded HttpOnly SameSite=Strict cookie, Secure for HTTPS. Never infer authority from peer loopback, Host or X-Forwarded-For. A printed development pairing link contains no secret; proof goes in a POST. The local pairing entry can be served by the same endpoint without exposing the secret. Electron establishes its same-origin cookie through session.cookies before navigation and retains no-account offline use. Cookie renewal must precede expiry/page-hide; all current operator fetches, including keepalive, carry it without a new async unload bootstrap.

A bearer proves a member identity, not operator access. Use the token's identity and active durable membership for the requested campaign/session; ignore claimed body/query participants. Specify credential precedence: when a request carries a member bearer, resolve it as that member and never silently fall back to a co-resident operator cookie on invalid/revoked bearer. An operator action can explicitly omit the bearer. Guest browser contexts receive no operator cookie. Co-op session creation is explicitly administrative: the route separately verifies the operator cookie and the creator bearer before binding the GM; it must not confuse the member-read credential precedence rule with permission to omit either proof. Member GET returns the existing canonical scoped snapshot, never a SerializedCampaign envelope with private state; B15-3 must adapt the guest refresh branch to consume that discriminated response, not merely change its header. Full-record write permission is operator or the actual authorized host-GM for the stored match, not any GM seat created for an arbitrary session. DELETE and adoption remain administrative per the matrix.

Co-op `matches/index.ts` is a required enforcement door: token verification currently permits a caller-supplied campaignId to reach GM-seat creation. B15-5 must require operator before any match, participant or host-registry side effect and remove the grants zero-seat bypass from both route and service. B15-5R completes the remaining doors as follows; no network-support claim is allowed between these units.

- **Redeem POST:** operator session plus verified recipient bearer matching token.participantId; retain existing embedded-public-key signature/expiry verification and source/replica conflict checks. Embedded-key verification does not authenticate a pinned issuer or body/sourceInstanceId provenance (`redeemCampaignGrant.ts:129-150`).
- **Replica-sync GET/DELETE:** operator authorization before status disclosure or stop effects.
- **Replica-sync POST:** operator plus verified recipient bearer matching body.playerId and presented participantId; campaignId/grantId match stored replica authority; presented expiry; operator-configured destination allowlist before dial. Missing policy or unknown destination refuses. Local authority stores role/sourceInstanceId/grantId/scopes, not a participant ID, pinned issuer key or socket address (`replica-sync.ts:28-38`). Do not promise a stored-participant comparison or local pinned-signature check. The source authenticates the grant on connection; persisting issuer/participant/address provenance is a separate unregistered schema follow-up.
- **Commands/rewind:** retain active-seat/per-intent/GM checks and project private response state; an operator cookie does not manufacture a co-op seat. Extend the real-verifier matrix to every campaign method and source/replica actor.

OB-2 and `FN-ob2-identity-before-hosted-deployment` remain byte-semantically unchanged. This is a **partial** follow-up for the operator-credential/member-access clause under Root's ruling; the identity/owner-column requirement for mutually untrusted operators remains open before multi-operator hosted deployment. No migration, legacy quarantine or first-caller owner assignment is registered. Do not claim full FN-ob2 closure when B15 finishes. U61 and PK-6-2b remain unchanged: solo needs no co-op seat and keeps client apply plus CAS.
