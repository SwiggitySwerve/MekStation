## Verdict

**REQUEST-CHANGES.** The projection logic is the right shape and matches the live replay path on _which events_ each viewer receives (probe-verified, see section 1). Nothing in the PR widens exposure. But a privacy fix needs proof that exercises the real pipeline and a wire-parity claim that holds, and three things fall short:

1. **F1 - The fixture seeds a branch the production mirror never writes.** The S1 mirror (`DurableMatchStore` -> `mirrorMatchBatchToJournal`) lands every `match` event on `branch_id = 'main'` (`MATCH_BASELINE_BRANCH_ID`) and installs the effective head as `main`; `ViewerProjectionService.readAuthorizedStream` reads `branch_id = ROOT_EVENT_BRANCH_ID = 'root'`. The PR test seeds on `root` and calls that "the shape the S1 mirror writes". Empirically (probe, section 1) a really-mirrored stream exports **zero** facts, so the fogged projection never runs on production data. Consequences: (a) the PR body's "the leak is live under the e2e arm and the shadow/enabled modes" is not true today - N6 is latent, not active (my r2 note described the code path correctly but did not check the branch id; that is the correction); (b) the PR's 8 tests prove the filter on a synthetic branch, not the route as deployed; (c) the moment someone points the export at the effective head (which has to happen - the route is useless as is, and rewinds activate non-root branches), F2 and F3 become live.
2. **F2 - `/private-preview` hands the 1v1 host the opponent's unrevealed sealed declarations.** `HostAsGmMembershipSource` brands the tactical host `gm`; `fogMatchHistoryProjection` then takes `isActorOwnedByViewer` (which returns true for any `gm`) and keeps every sealed `MovementDeclared` / `AttackDeclared` / `PhysicalAttackDeclared` for the host before the reveal. The live wire brands that same host `player` (durable seats never stamp `gm`; `MatchSeatMembershipSource` only does for a campaign GM row), so live withholds them. Probe (section 1): host `/private-preview?ref=no-such-ref` returned the opponent's unrevealed `attack_declared` (`OPP-SEALED-ATTACK=true`) while host `/export` and host live replay did not. The PR body's "host gets the owner view, as on the live wire" and the test "host private-preview: the same fogged stream as its export" both hold only because the fixture has no opponent sealed declaration. Mutant M9 (ignore `gm` for sealed) survives 8/8 - the suite cannot see this at all. The ref need not exist; any seated host can call this mid-phase.
3. **F3 - Authority-only fields ride out to players.** The kept `matchEvent` still carries `sequence`, `visibility`, and (if present) `privateRecordRef`. The live wire removes exactly these for non-GM viewers in `ViewerFrameProjector.AUTHORITY_ONLY_EVENT_FIELDS`, citing `multiplayer-sync` _Authority and Viewer Sequences Are Separate_: "Player payloads SHALL NOT expose hidden authority identifiers or gaps that reveal concealed events." Under fog the PR's own `sequenceHint` is gapless, but the embedded `matchEvent.sequence` is not: in the probe the host export carried 2,3,4,6,7,9 - the holes at 5 and 8 count the opponent's concealed events, the channel the spec names. The fog-off export has always carried `sequence`; what is new is that fog-on now produces _gaps_ in it. The PR body ("Withheld facts carry no delivery identity") addresses `sequenceHint` only.

Each fix is small and local; see section 6 for the recommended changes. Re-review needed after.

## 2. Viewer identity and privilege (brief item 2)

- Identity: `prepareMatchHistoryGet` -> `authenticateRequest(req, undefined, {kind:'match', id})`. The bearer (header, or `?token=` for WS-style clients) is an Ed25519-signed token; `playerId` is recomputed from the public key (`derivePlayerId`) and compared, and the signed scope must equal the URL match id. `caller.playerId` is the only principal the service sees; no query/body parameter names a viewer. `exportForViewer(principalId, matchId, ...)` re-resolves the brand from durable seats on every call. No spoofing path found. Mutant M8 (filter as `meta.hostPlayerId` instead of `viewer.principalId`) is killed, but by a single test.
- Spectator detection uses `meta.seats` + `isSpectatorPlayer`, same as live.
- GM: live derives `gm` only from a durable `campaign_session_participant` row with seat `gm`. The HTTP preview route adds a second source of `gm` (host remap) and the PR honors it for sealed choices. That is F2. The route's own header comment ("a widening of this caller's own view of its own match, not of any player's") was written for the identity projection and is now wrong under fog.
- Spec check: `fog-of-war` _Replay Reflects Fog History_ / "Post-match unfiltered log privileged" requires the filtered log for a non-privileged player and says the unfiltered log needs privileged access. A 1v1 host is not a privileged referee; _GM Intel Override_ is a separate GM shell projection. The PR's choice of filter-not-refuse is consistent with the spec; the GM-brand carve-out on the preview route is not.

## 3. Fail-closed and performance (brief item 3)

- Fail-closed: `projectionFailed()` throws `ViewerProjectionError('projection-failed')` before any fact is pushed in `matchEventOf`, `statesAfterEach`, the missing-meta branch, and the `afterRevision !== 0` branch. The route maps it through `rejectMatchHistoryFailure` -> `sendCaughtApiError` -> 500 with the constant message. `ViewerHistoryService.exportForViewer` builds the body only after `project()` resolves, so no partial body can be written. The PR test "fails closed on a match envelope it cannot read" confirms a 5xx with no secret in the body. Note `applyEvent` is a reducer that tolerates unknown payload shapes for most types, so "fold that throws" is a narrower guard than the PR text suggests; the envelope-shape check is what caught the test's malformed row.
- `afterRevision > 0` refusal: correct (a mid-stream page has no honest prefix state). Untested (mutant M6 survives). No HTTP caller passes it today.
- Performance: one `applyEvent` per event plus one `filterEventForPlayer` per event with a per-request `FogOfWarVisibilityCache`. O(n) in events (the live replay path is O(n^2): `deriveState(prefix)` per event). `readAuthorizedStream` caps at `EVENT_JOURNAL_MAX_PAGE_SIZE = 500`, so n <= 500 per request; this also means a long match's export is silently truncated to the first 500 revisions - pre-existing, and under fog the truncation errs safe (a declaration whose reveal falls past the page is treated as unrevealed). `withSideAssignments` allocates a new state object per event, which defeats the visibility cache's identity check (always a miss) - correctness unaffected, cost is one extra ownership walk per event. Acceptable.

## 6. Requested changes

1. **Seed the fixture with the real mirror.** Replace the hand-rolled `journal.append({expectedBranchId: ROOT_EVENT_BRANCH_ID})` with `mirrorMatchBatchToJournal` (or `DurableMatchStore` in `shadow` mode). The test will then show the export returning nothing, which is the pre-existing root/main mismatch. Either fix the export in this PR to read the stream's effective head (`SQLiteEventHistoryBranchStore.readEffectiveHead` is what `readMatchHistoryLineage` already consults) with the fog projection following it, or split that into a sibling PR and rewrite this PR's description so it does not claim an active leak or a mirror-shaped fixture. Both are acceptable; what is not is a privacy proof on a branch production never writes.
2. **Do not let the preview route's host-as-GM brand unlock sealed choices.** Options, author's choice: (a) in `FogAwareMatchProjectionService`, derive the sealed-choice audience role from the durable seat source (`MatchSeatMembershipSource`) rather than `viewer.role`; (b) have `matchPrivatePreviewRoute` project the `match` stream through the seat-derived viewer and use the GM brand only for the private-record read; (c) in `fogMatchHistoryProjection`, evaluate `isActorOwnedByViewer` with `role: 'player'` unless the viewer's GM role is seat-derived. Add a test with an unrevealed opponent `AttackDeclared` and assert the host preview omits it (kills M9).
3. **Strip authority-only fields for non-GM viewers.** Run each kept event through `projectEventForViewerClass(event, viewer.role)` from `ViewerFrameProjector` (or remove `sequence`/`visibility`/`privateRecordRef` for `player` role) before building the fact, so the HTTP export obeys the same `AUTHORITY_ONLY_EVENT_FIELDS` policy as the wire. Assert in the fog-on tests that no fact's `matchEvent` carries `sequence`.
4. **Strengthen the suite:** LOS-change case (kills M1), an `afterRevision > 0` refusal test (kills M6), and fix the test header / PR body wording about the mirror shape.
5. Follow-ups to file, not blocking: `GET /api/multiplayer/matches/:id` participant gating and payload trimming; fog-off sealed declarations in the export; export page cap of 500 revisions; the live wire's post-reveal `MovementDeclared` of hidden units.
