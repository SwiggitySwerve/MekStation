## G2-BOOT-1: options and privacy/authority contract

1. **Full metadata GET: reject.** The returned `IMatchCoopCampaignRegistration` holds both campaignId and raw state (`IMatchStore.ts:102`). The route is now unavailable to an ordinary unseated invitee, and fetching it as a permitted principal still discloses state in the browser. Ignoring fields in JavaScript does not undo disclosure. Its GET and concurrent DELETE are outside this implementation.
2. **Authenticated identity-only invite mode: recommend.** `src/pages/api/multiplayer/invites/[roomCode].ts:55-65` already resolves a live code and constructs a narrow response. Add an explicit `campaignIdentity=1` query mode used by the entry panel, with its freshly minted bearer in the Authorization header. In this mode return only `{ matchId, status, layout?, campaignId }`. The ID comes exclusively from `meta.coopCampaign.campaignId`; do not serialize or spread meta, coopCampaign, state, seats, bootstrap data, grants or tokens. The normal anonymous response remains exactly its existing summary, without campaignId.
3. **Unbound bootstrap then bound rejoin: reject for G2.** It could acquire identity from an already authorized/projected snapshot, but contradicts the registered all-creators-bound-in-one-change condition and adds an avoidable two-connection transition. If ever separately selected, every bootstrap offer/numeric observation has **zero applied-view, readiness, grant or durable-receipt credit**, no readonly campaignId mutation, and only a fresh authorized baseline on the bound connection may establish application proof. That would require an explicit behavior amendment and additional tests; it is not silently permitted here.

The selected endpoint is an identity response, not a seat-admission endpoint. CampaignId is a stable routing/correlation identifier, potentially privacy-relevant and not assumed random; it is **not** a secret credential or authority capability. Only a caller with a valid bearer and the current resolvable invite learns the additional ID. A bearer alone, a matchId alone, an expired/unknown code, or the existing anonymous summary cannot obtain it through this mode. This deliberately permits an unseated invitee to learn identity so it can construct the bound join. A revoked person who still holds valid credentials and the current code can learn this identifier, but cannot regain a seat, state or receipt authority. Do not represent bearer authentication as membership.

Use the delivered verifier and server-derived scope: `{ kind: 'campaign-session', id: meta.matchId }`, never a caller-provided scope. Existing unscoped identity-token compatibility remains whatever `authenticateRequest` currently implements; mismatched scoped tokens must fail. Require a non-empty Bearer Authorization header before invoking it: `auth.ts:276` otherwise falls back to a query token, which this new mode must not accept or encourage. Invalid/missing authentication returns 401 without identity. Unknown/expired/non-coop or invalid campaign identity returns the same 404 class without private detail. Reject malformed identity-mode queries rather than downgrading to a summary. Send `Cache-Control: private, no-store` for identity-mode successes and failures; never cache this response in the client. Preserve anonymous lobby discovery behavior.

Live-code resolution is already status-limited by `DurableMatchStore.ts:1693-1700` and `InMemoryMatchStore.ts:466-473`; preserve that rule. This design does not revive expired codes or add an active-session discovery path. Existing returning members use their saved campaign identity/token, not this onboarding resolver.

No seat is claimed by HTTP. The bound WS authenticates independently, derives the principal/role, rejects revoked membership (`bindCampaignSyncConnection.ts:1162-1185`), routes existing members (`:1269`), validates guest grant/code, and reserves the seat before hydration (`:1293-1354`). A code expiring, rotating, filling, or being revoked between HTTP and WS is refused by that boundary. expectedCampaignId is a local consistency binding, not proof of membership; it does not enter legacy join bytes or bypass a server check.

The entry panel currently resolves only matchId/status (`CampaignCoopEntryPanel.tsx:105-119`), then creates the socket at :328 and obtains campaignId from the snapshot at :346. Change its real request, typed response and runtime validation together. Require non-empty matchId/campaignId and valid status, use the same resolved matchId and normalized code for the creator, and bind expectedCampaignId before construction. No generated ID, cast-only field, matchId substitution or raw-metadata fallback. Validate the eventual snapshot's event and state campaign identity against the resolved identity **before** mirror initialization/adoption. A stale attempt or mismatched snapshot cannot adopt or certify anything.

Exact proof leaf: `src/__tests__/api/securityBoundary.test.ts`. Root requested a non-colliding test if the original path was already owned: `src/__tests__/unit/api/multiplayerMatchMeta.test.ts` falls under completed U35c/U35d/U35e grants, so it remains an unchanged privacy regression control (actual invite import :27; anonymous exact-response assertion :266-285). The selected existing API-security suite has no unit ownership overlap. Its current auth/store defaults are mocks (`securityBoundary.test.ts:14-28`), so the new isolated describe block must delegate authentication to `jest.requireActual` and room-code lookups to a real `InMemoryMatchStore`, use generated signed tokens and the actual invite handler, and restore the existing defaults between cases. No success-only mock counts as cryptographic proof; no unregistered helper or placeholder test is added. Required RED cases:

- Anonymous normal resolution retains its exact prior shape; identity-mode missing/invalid/expired/signature-invalid bearer, query-token-only authentication and wrong scoped token disclose no ID. Matching campaign-session scope succeeds. Assert no-store headers.
- Unknown/malformed/expired/rotated/non-coop code and malformed durable campaign identity produce no identity; test missing and malformed query shapes and method handling. Preserve status expiry using the real store fixture.
- HTTP identity lookup changes no seats, membership or receipts. Existing WS revocation/full-seat/expiry refusal controls remain required unchanged; if a new server test leaf is actually necessary, stop and split/register it.

## G2-RESEAT-1: frozen A-to-B subscription contract

Delivered APIs are `getActiveCampaignSyncTransport`, `onFrame`, `onError`, the returned unsubscribe closures, guarded `close`, and `connectStoredCampaignSyncTransport` (`campaignSyncTransport.ts:59-80,398-419,541-581`). E's receipt-mode unexpected close emits its existing recovery error (`:523-526`). F consumes it; the consumer's `rejoins` state is private to the connected surface (`useCampaignApplicationConsumer.ts:242-257`). A sibling launch page does not observe it. The current launch page captures transport A once at `launch.tsx:177-205`. The getter is not a subscription and cannot by itself reseat this closure.

Register `src/lib/campaign/coop/campaignSyncTransport.ts` and its existing `__tests__/campaignSyncTransport.test.ts`. Add the small registry-observation API `subscribeActiveCampaignSyncTransport(matchId, onChange): () => void`. It notifies identity changes after the authoritative map has changed. It is an invalidation signal, not receipt/seat authority. Callers subscribe then immediately reconcile through the getter (closing the initial-read/subscription gap). Notify synchronously before any subsequent socket frame can be dispatched. Cover direct connect, explicit register/replacement, guarded unregister, explicit close, unexpected close and test reset. Do not poll or couple siblings through F's private hook state.

Lifecycle rules:

1. Subscription state holds the exact subscribed transport and its own frame/error disposers. On notification, re-read the getter, detach A first, then attach B only if matchId, campaignId, playerId and role match the mounted binding. Null/foreign identity leaves the subscriber detached; never close/adopt a foreign transport. Every callback rechecks both the active object and its attempt/effect generation before acting.
2. A-to-null-to-B during recovery is allowed. A late close/unregister from A cannot delete B or emit a false removal; preserve existing object-identity delete guards. Same-object registration must not duplicate listeners or re-send participation. Reentrant notification and a throwing observer must not corrupt registry state, suppress other listeners, or prevent close; route diagnostics through the existing logger. Subscribers never create or close sockets merely in response to notification.
3. Launch participation sends resolve the active getter at execution time and check binding identity. On B installation, attach its frame listener immediately and re-send the latest current local choice once for B (without inventing an application ACK/readiness). Read current force/mission/choice after any continuation; validate incoming match/mission/force and callback generation before publishing. A late A frame/error must publish nothing. Do not rely on a campaign store render to install B's listener; the first B participation frame must be observed.
4. Entry snapshot waiting also reconciles through this mechanism, with one fixed overall timeout, an attempt generation, and cancellation/unmount disposal. Recheck active identity after awaits and before mirror adoption or navigation. All five creators bind actual campaign identity; missing or foreign active transport cannot be silently reused or overwritten. Creating a transport remains an explicit owner action, not an observer side effect.
5. Cleanup calls the disposers belonging to the actual A/B subscriptions; using the current getter to guess an old unsubscribe is wrong. Read the getter before destructive cleanup. Entry failure closes its originally created A only if A is still active and the attempt still owns it. A stale error/timeout must never close replacement B. Launch cleanup owns listeners, not the shared socket. After successful navigation, entry relinquishes ownership and subscriptions without closing the handed-off connection. Dispose registry observers on unmount/campaign or mission change; clear reset listeners safely in test teardown.

The new API is a **required registered E-owned seam outside today's G2 leaves**, not a claim that E delivered a replacement listener. Keep E's existing lastSeq, error prefix, numeric ACK/receipt latch and confirmation semantics byte-for-byte compatible. No `useCampaignApplicationConsumer.ts` or persistence-store write is planned. Recheck F/G1 when verified; another required owner leaf triggers registration/split, not implicit authority from this design.

Required proof in the newly registered transport suite: direct/register replacement, subscribe-before-read, same-object idempotence, close/unregister identity guards, remote-close recovery, reset/unsubscribe, observer exception and reentrancy. In already-owned entry/launch suites exercise real transport plus in-file socket factories: attach A, trigger consumer-style close/rejoin, install B, deliver B's first frame **without an unrelated render**, and prove B receives the current choice while A cannot publish/send/close B. Hold entry awaits and stale callbacks across replacement/unmount; assert listener disposal and identity mismatch handling. Preserve F/G1 tests unchanged and do not claim static probes are runtime RED/GREEN.

With a fixed clock/token, compare raw bound/unbound CampaignJoin bytes including positive lastSeq, and numeric CampaignAck bytes before any genuine offer. Check expectedCampaignId at all five original call sites with campaignId != matchId. Binding alone must neither latch receipt mode nor grant applied-view credit. Genuine matching offers follow the existing consumer/fact/apply-before-confirm path.
