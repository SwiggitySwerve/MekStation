## Failure semantics (review item 2)

- **Observer-only / delayed consumer:** no ACK without an explicit `confirmApplied(offer, {status:'applied'})` on the exact frozen issued object. Tests: "observer-only and delayed consumers provide no proof" and the gated async happy path.
- **Throwing / rejecting consumer:** a synchronous success recorded during dispatch returns `prefix-pending` (`:179`). A later observer throw in receipt mode recovers before the post-dispatch drain (`:406-419`). A failed outcome triggers `recover('application-failed')`, after which completions are refused as `stale-offer`. No promises are created in the transport, so it has no unhandled-rejection surface.
- **Wrong campaign / match / kind / prefix, malformed present metadata:** presence is classified on the raw body before schema stripping (`parseServerMessage`). Invalid present metadata latches receipt mode and recovers rather than falling back to a legacy frame.
- **Closed transport:** explicit `close()` and spontaneous `onclose` both clear `pending`/`sent` and set `closed`. Late completions return `refused: closed`, and late server ACKs are ignored. Receipt ACKs never enter `pendingOutbound`; a non-open socket or a throwing `send` returns `recovery-required: send-failed`.
- **Double ACK / non-contiguous ACK:** drain sends only when the FIFO is fully applied and `latest !== sent`, so the ACK is always the latest delivered receipt over a complete contiguous prefix. Re-completion returns `already-completed`.
- **Pending bound:** the 65th outstanding offer recovers with `pending-overflow`, keeping the head and never collapsing the queue (`:243`). Tests cover exactly 64 completing and 65 overflowing.
- **Campaign cross-talk:** the mirror now refuses foreign-campaign snapshots (non-replacement) and events. A cached transport with a different binding cannot be retargeted (`connectStoredCampaignSyncTransport`).

## Server authority, fog and type hygiene (review item 3)

Clients still only send intents and ACKs. The new code resolves no canonical actions and introduces no fog exposure: hydration facts are server-supplied and only observed. There is no `Math.random`/`Date.now` (the `ts` uses the existing `nowIso()`, outside seeded paths), no browser SQLite/fs import, and no `any`. The two casts (`message as ICampaignApplicationOffer` after a kind check and `appliedView` truthiness) are sound narrowings. Legacy frames without metadata still parse through the unchanged shared unions. `Protocol.test.ts` asserts that legacy `CampaignSnapshot` parsing and legacy unknown-field stripping are preserved.

## Findings

1. **minor — completion recorded during a non-offer dispatch never drains.** `campaignSyncTransport.ts:179` returns `prefix-pending` whenever `dispatching` is true. The only post-dispatch drain is `if (offered && !failed && !closed) drain()` at `:419`. Scenario: a consumer confirms a pending offer from inside an `onFrame` callback while a non-offer frame (an `Error` frame or a legacy metadata-absent event) is being dispatched. The entry is marked applied and the call returns `prefix-pending`, but no ACK is sent until another offer is drained or the same offer is confirmed again. This is liveness only; no unsafe ACK is possible. My evidence is static control-flow reading; I wrote no probe because this review is read-only. Suggested fix: drain after any dispatch while `pending.length > 0` (one-line condition change plus a test), in P2CD or as the first Task 13 consumer-wiring item.
2. **minor — the legacy numeric-ACK tests were not relabeled as the addendum requires.** Addendum §5 asks that the two base numeric-ACK tests become explicitly labeled legacy compatibility controls, "correcting their claim that void observation proved application". The tests at `src/lib/campaign/coop/__tests__/campaignSyncTransport.test.ts:796` ("acks a resync snapshot with the revision it carries", whose comment ends "acking that revision is honest") and `:836` ("acks each applied CampaignEvent…") are unchanged. The production comment was corrected; the test names and comment were not. Recommend renaming them to "legacy observation ACK (no application proof) …" before or at P2CG1.
3. **minor — modularity guardrail exceeded (review item 5).** `campaignSyncTransport.ts` grew from 419 to 636 physical lines, about 371 to 590 counted by oxlint (`max-lines` with skipBlank/skipComments, max 400). That introduces a new lint warning; the warning count stayed at 84 with 0 errors because Protocol.ts already warned at base. `docs/FILE_MODULARITY_SPEC.md` split triggers 2 ("Runtime logic file exceeds 500 lines") and 3 (already over soft max 400, grew by more than about 40 lines) both fire. The file now mixes socket/heartbeat orchestration with the receipt ledger (spec §Responsibility Heuristics). **Recommendation: accept as a registered-owner exception for this PR. Do not request a split now.** Reasoning: `units.json` P2CD `ownershipPaths` does include the parent `src/lib/campaign`, so the validator would mechanically admit a new sibling module. The plan, however, forbids broad parent permission and limits the accepted staging to six exact leaves, so a split leaf would need a new exact registration. Condition: record a concrete follow-up to extract the receipt ledger (`recover`/`drain`/`registerOffer`/`freezeApplicationFrame`, about 120 lines) behind the existing facade when P2CG1 next owns this file (P2CER already registered it there). That task removes the numeric generator, so the extraction lands naturally then.
4. **minor — a server confirmation is dropped once a newer offer has arrived.** The guard `sent === latest` (`:387`) drops a valid server confirmation for the actually sent receipt when a newer offer has been delivered but not yet completed. This is defensible as the recipe's "stale/superseded confirmation" rule, and the next cumulative ACK will be confirmed. Task 13 consumers must not wait for a confirmation per receipt. Separately, a throwing confirmation handler (`:394`) propagates out of `onmessage` uncaught. This is informational; no existing handlers are registered.
5. **minor — duplicate detection compares whole frames, including envelope `ts`.** `JSON.stringify(duplicate) !== JSON.stringify(frame)` (`:218`) includes the outer `ts`. A server re-delivery of the same receipt with a refreshed timestamp is treated as a conflicting body and forces recovery. This fails closed, so it costs liveness, not safety. Task 12 must re-send byte-identical frames or not re-send at all; note it in the Task 12 contract.
6. **minor — recovery reason label for an unbound offer.** An offer arriving on a transport with no `expectedCampaignId` recovers as `prefix-conflict` (`:208`), although the result union has a dedicated `unbound` reason. This only affects error diagnostics.
7. **info — negative tests are partly vacuous against base.** `round3-red.log` shows 36 failed / 59 passed. Several negative rows ("rejects invalid offers: wrong-match/wrong-campaign/missing-bundle/malformed/no-join/unbound") passed before implementation, because base never acked anyway. They carry weight only together with the positive happy-path tests, which do fail at RED. Five tests (95 → 100) were added after RED: the join-send guard and the legacy unknown-field cases. Root disclosed this in `round3-report.md`. The RED/green history is coherent: every RED failure is a new P2CD test, and no pre-existing test failed.
8. **info — the mirror's cross-campaign guard is a narrow behaviour change for legacy callers.** `campaignMirrorStore.ts:247`/`:276` now refuse a foreign campaign without `reset()`. On base, the same foreign events could layer onto the held state (cross-talk), so this only tightens behaviour. `CampaignCoopRouteSurfaceConnected.tsx:319-321` calls `beginMirror` only when `!peers`, so a campaign switch in one session still relies on reset/begin elsewhere. That is pre-existing behaviour, outside P2CD.
