## 2. Security

- **Renderer hardening unchanged.** `main.window.ts` `webPreferences` at head: `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`, `webSecurity: !developmentMode`; the diff touches none of these lines. Packaged CDP probe: `typeof process === 'undefined'` in the renderer.
- **Preload API surface unchanged.** The only `preload.ts` hunk converts imports to type-only and inlines the four channel maps; the `contextBridge.exposeInMainWorld` body is untouched (31 bridge keys observed in both packaged runs, same as before). No new channels, no new privileged capability. The `preload.sandbox.test.ts` static check is regex-based and conservative (inline `type` modifiers would false-positive), which is acceptable.
- **Updater.** Default feed is now `provider: 'github'` (`SwiggitySwerve/MekStation`) over HTTPS; `autoDownload = false`, `allowDowngrade = false`. Download happens only after the user clicks in `notifyUpdateAvailable`; install only after `update-downloaded` + user "Restart Now" (`quitAndInstall`) or electron-updater's default `autoInstallOnAppQuit` on Windows — both pre-existing. electron-updater's normal Windows protections (TLS feed, sha512 from `latest.yml`; no publisher check because the builds are unsigned) are unchanged; this PR adds no code-execution path beyond that. `MEKSTATION_UPDATE_FEED_BASE_URL` still accepts an arbitrary generic feed (any scheme) — pre-existing, env-level trust, see note N3.
- **macOS never auto-installs.** `initializeAutoUpdater` returns before `setFeedURL`/`checkForUpdates` and sets `autoInstallOnAppQuit = false`. All other `autoUpdater` entry points were traced: `main.behavior.ts:56`, `main.ipc.ts:244`, `main.tray.ts:80` all go through `MekStationApp.checkForUpdates()` which on mac opens `RELEASES_PAGE_URL` and returns; `downloadUpdate` (main.actions.ts:75) is reachable only from the `update-available` event and `quitAndInstall` (main.actions.ts:128) only from `update-downloaded`, neither of which can fire without a check.
- **Process kill scope.** `killProcessTree` runs `taskkill /pid <child.pid> /T /F` only on the `ChildProcess` this module spawned, guarded by `exitCode === null && signalCode === null`. On Windows libuv holds the process handle until exit is observed, so the PID cannot be recycled to a foreign process while that guard is true. No wildcard, no image-name kill. Packaged run2 `close-check.txt`: the tree `19824,42472,10372,54624,6612` was gone within 1 s and nothing listened on 3001.
- **Loading page.** `data:` URL, inline CSS only, no script; `will-navigate` still gates on `appOrigin`; the `reopenLastUnit` → `open-unit` IPC is now additionally gated on `getURL().startsWith(appOrigin)` so it cannot fire on the loading page.

## 3. Correctness

- **Server crash before ready:** class-level `exit` handler clears `child`/`ready`; the per-wait `once('exit')` rejects with `exited before it was ready (code, signal)`; the next `waitUntilReady` respawns. Tested + M-kill.
- **Marker split across chunks:** rolling 4 KiB `pending` buffer, marker is 25 bytes. Tested + M4.
- **Port already in use:** `server.js` has no `listen` error handler or `uncaughtException` handler, so EADDRINUSE throws → child exits code 1 → wait rejects → Retry/Quit dialog. Bounded by the user; Retry respawns and fails again. Dialog detail is only `exited before it was ready (code 1, signal null)` — the actual reason stays in main-process stderr (see N1).
- **Timeout:** 120 s, rejects, removes its own listeners (no leak across retries); the child keeps running and a later wait sees `ready` without respawn. Tested.
- **Retry restarts cleanly:** `start()` reuses a live child and only spawns when `this.child === null` (set on exit/error/stop). One server per process (`getEmbeddedServer` singleton), reused by a re-created macOS window. No duplicate spawn path found.
- **Quit path:** `before-quit` state machine idle → running (preventDefault, `Promise.race([cleanup(), 10 s])`) → done → single `app.quit()` → second `before-quit` passes → `will-quit` stops the server (idempotent; `stop()` nulls `child` first). No re-entry loop (M5). `cleanupServices` stops the server in `finally` even if a service cleanup throws (M3). `MekStationApp.cleanup()` keeps its own `isCleaningUp` re-entry guard. Window `close` no longer `preventDefault`s on Win/Linux so `window-all-closed` → `app.quit()` fires.
- **Tray failure:** `new Tray()` wrapped; `createSystemTray` returns early and `setupIpcHandlers` runs. Proven by run2 evidence; no unit test.
- `dialog.showMessageBox` rejecting inside the `void loadPackagedUi(...)` would surface as an unhandledRejection (main.ts logs it) and leave the loading page — edge case, acceptable.

## 4. Behaviour change: close = quit on Windows/Linux

Acceptable. There was no hide-on-close setting, no user-facing doc describes hide-to-tray (grep of `docs/`, `desktop/`, `README.md` finds none; no `CHANGELOG`), the tray icon asset is missing in the shipped build anyway, and the old behaviour is exactly the L0-08 "app keeps running" symptom. macOS convention is preserved. The change is documented in the PR body only — see N2.

## 5. Notes (non-blocking)

- **N1 — make the startup failure actionable.** Buffer the last ~2 KiB of child stderr in `EmbeddedServer` and append it to the rejection message, so an EADDRINUSE (or module-load) failure is visible in the Retry/Quit dialog instead of only in the main-process log. Cheap; could land in v2.1.1 or next.
- **N2 — release notes.** The v2.1.1 GitHub release notes should state: (a) closing the window now quits on Windows/Linux; (b) users who ran v2.1.0 may still have its orphaned main+server tree alive (L0-08). That old main process holds the single-instance lock, so a fresh v2.1.1 launch will `app.quit()` immediately and just focus the old blank window; portable users must end `MekStation.exe` in Task Manager (or sign out) once before first launch. This is a v2.1.0 consequence, not something this PR can fix in code.
- **N3 — updater env override.** `MEKSTATION_UPDATE_FEED_BASE_URL` is pre-existing and env-level trust, but if kept, consider rejecting non-`https:` values. Not a regression.
- **N4 — POSIX kill.** `child.kill('SIGTERM')` with no SIGKILL escalation and no process-group kill; the code comment acknowledges it. Low risk because the standalone server does not fork, but `detached: true` + `process.kill(-pid)` would make Linux/mac symmetric with the Windows `/T`.
