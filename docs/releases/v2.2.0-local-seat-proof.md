# v2.2.0 installed local-seat proof

Evidence record and procedure for roadmap Step 2 (LSC-2P). This file is a record of one run, not an acceptance record: it does not close Step 2, grants no gate, and a local PASS never replaces the exact-main proof. Root verifies the run; the checker (`local-seat-proof` in `scripts/qc/v220-evidence.mjs`) only checks completeness.

Scope: one installed Windows x64 NSIS authority at `http://127.0.0.1:3001`, three isolated Chromium profiles (GM, P1, P2), ordinary shipped UI only. The installer is unsigned and is a pre-RC build; Step 8 must re-run this command on the RC installer so the hashes bind.

## Procedure

Use Windows PowerShell, Node 22 and a clean checkout of the commit under proof. Run heavy steps through `_locks/heavy-run.mjs`. Never set `GH_TOKEN`; electron-builder runs with `--publish never`.

1. Candidate: `$rc = git rev-parse HEAD`; the tree must be clean.
2. Install: `npm ci`, then `npm --prefix desktop ci` (the desktop package has its own lockfile).
3. Build: `npm run electron:build`, then from `desktop/`: `npm run rebuild:next-standalone` and `npx electron-builder --win nsis --x64 --config.extraMetadata.version=<ver> --publish never`.
4. Hash the installer (`Get-FileHash -Algorithm SHA256`) before anything touches it.
5. Pre-check: no `MekStation.exe` may be running (the single-instance lock is per user-data dir, so a second profile starts a second app whose server fails with EADDRINUSE), ports 3001 and 3600 are free, and `Env:ELECTRON_RUN_AS_NODE` is cleared.
6. Silent per-user install into a fresh run directory without spaces: `Start-Process $installer -ArgumentList '/S', "/D=$inst" -Wait`. The silent install does not launch the app.
7. Launch from a scrubbed environment. Remove `NEXT_PUBLIC_E2E_MODE`, `PLAYWRIGHT_E2E_RUN_ID`, `MEKSTATION_E2E_SERVER_COMMAND`, `MULTIPLAYER_STORE`, `DATABASE_PATH`, `PORT`, `HOSTNAME`, `NODE_ENV` and `ELECTRON_RUN_AS_NODE`, then **set** `MULTIPLAYER_DB_PATH=$run\userdata\data\multiplayer-matches.db` (`--user-data-dir` does not move the match store). Start `MekStation.exe --user-data-dir=$run\userdata` with `-WindowStyle Hidden` and redirect stdout and stderr to `$run\app-stdout.log` and `$run\app-stderr.log`.
8. Environment and command (about 70-75 minutes; tell Root before the run because it exceeds the heavy-run lease):

```powershell
$env:LSC2P_INSTALLER = $installer
$env:LSC2P_INSTALLER_SHA256 = $sha
$env:LSC2P_INSTALL_DIR = $inst
$env:LSC2P_RC_SHA = $rc
$env:LSC2P_RUN_DIR = $run
node scripts/playwright/run-playwright.mjs test --config=playwright.local-seat-packaged.config.ts e2e/local-seat-credentials.spec.ts --workers=1
```

Prerequisite: `npx playwright install chromium`. Development loop (not qualifying): append `--grep-invert @soak`, which also skips N5 because N5 runs at the end of the soak test (its 61 s quiet period and 60 s lockout cannot fit the unchanged 30 s test timeout; only the soak test overrides it). The machine must not sleep; a lost tab is a FAIL.

9. Teardown: the spec's S7 leaves the relaunched app running. Close it with a graceful `WM_CLOSE` to its `Chrome_WidgetWin_1` window (a hidden window ignores a plain `taskkill`; `/F` is a recorded fallback), run `"$inst\Uninstall MekStation.exe" /currentuser /S`, then delete `%LOCALAPPDATA%\mekstation-desktop-updater` (installer copy), `%TEMP%\~nsu.tmp\Un_A.exe` and `$run` after checking each resolves under the expected parent.

## Non-hermetic inputs

The app checks GitHub for updates at each start and fails softly. The installed exe reports `ProductVersion` without the pre-release suffix, so the record keeps the installer's own product version and never asserts equality. SQLite WAL files stay beside the databases after a clean quit.

## Known gaps

- The browser password-manager prompt cannot be observed by Playwright; `autocomplete` attributes are checked (CF-LSC2OP-4) and the interactive check stays a human item in Step 8.
- Windows x64 NSIS only; macOS and Linux installers are not covered. The installer is unsigned.
- No removal control exists for a ghost participant, so the packaged claim stops at: re-provision gives a new playerId, the guest reclaims, the host refuses the new identity while the ghost holds a seat (Q8).
- S5b is test-only evidence for the owner ruling on Q8(b). Campaign B never held the old seat-2 identity, so S5b shows that a re-provisioned identity is admitted where a tactical seat is free; it does not run the admission's longer sequence (old identity joins B, re-provision, new identity takes the remaining seat while the ghost stays). It removes no ghost and claims no readmission into campaign A.
- The per-match forget control renders only inside the four-minute window or on a stored problem (CF-LSC2-F6); the journey reclaims through a new tab.
- Restart recovery of the match host and the `InMemoryPlayerStore` warning are observations (CF-SMOKEA1-7), not pass conditions.
- This record binds a pre-RC installer built from the commit under proof; it is a done-test packet, not RC qualification.
- Known issue, disclosed and not fixed in v2.2.0 (owner decision 2, roadmap F1): after the re-provisioned guest joins a second campaign, the same profile opened on the first campaign shows the HOST badge and the host review surface (S5b observation 3, recorded in the record above). N4 is asserted before S5b and passes; S5b changes the profile afterwards. Step 2's claim is no implied server authority, with this issue disclosed. The F1 investigation (2026-10-24) also found a security half: from that view the dashboard's whole-record save is accepted by PUT /api/campaigns/[id] (the route trusts body.coopSession), and an anonymous DELETE of a live-host campaign answers 204. The campaign socket is not affected; it takes the role from the verified bearer. CAMPAIGN-LIVE-WRITE-1 (release-blocking) owns that fix; it is not in this build, so the security half is open here. This run checks host surfaces in the UI (N4) and distinct verified principals (S1); it does not attempt a host action from a guest profile, and it proves no implied server authority only through those checks.
- Restart: seats and playerIds were unchanged and the `InMemoryPlayerStore` dev-only warning was seen (CF-SMOKEA1-7). The record's `matchRecovered: no` comes from the spec's heuristic, which reports no when any socket closes after the reload. After the restart the authority log (`app-restart-stdout.log`) shows the GM and P1 sockets accepted and bound to campaign A; the only refusal was P2's original seat-2 bearer, which had expired at 19:18:44Z (upgrade rejected, reason=expired). The observation is inconclusive, not a recovery failure and not a product defect; STEP2-RC-RERUN-1 should record recovery per profile. These are observations, not pass conditions.
- The CF-SMOKEA1-7 decision is still open: identities survive a restart (playerIds come from keys and the seat rows are in SQLite), but player profiles held by `InMemoryPlayerStore` are lost. Closure must either rule that no repair is needed or register a profile-persistence follow-up; P2J depends on it.
- The app does not reconnect a closed campaign socket by itself (F4); after a socket drop or an authority restart each player must reload. S2 and S7 reload explicitly. In a bare second tab the BINDING_REQUIRED text does not render (F5); S2c records this and does not assert it.
- The spec keeps its `MULTIPLAYER_DB_PATH` override of the match store; STEP2-RC-RERUN-1 reruns Step 2 on the RC build and removes it.
- After the qualifying run, one unused helper (`same`, two lines) was removed from the spec because `lint:units` found it over the ceiling; no behavior changed. The run proved the spec at `d302868b3`; the later spec differs by those two lines only.
