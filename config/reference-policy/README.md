# Pinned reference policy

The policy generator derives expectations for every in-scope pinned source from
immutable Git objects and native verifier contracts. It accepts no native
reference or comparator result as an input. A generated proposal requires Root's
explicit approval before the live trust proof; generation does not approve it.

```text
python -B scripts/megameklab-conversion/reference_policy.py --runtime-root <retained-runtime-reference> --config-receipt <accepted-verifier-config.json> --out config/reference-policy --node <node22>
```

Run through the existing serial heavy queue. The generator invokes the
repository's oxfmt owner. Generate twice into separate external E: directories
and compare both generated files byte for byte before publishing them here.

`expected-reference-policy.json` follows P6's version-1 trust schema.
`derivation.json` cites the pinned source bytes and the rule for each unit and
setting. Unrecognized source expressions produce explicit null expectations and
an enumerated unspecified reason. They never become a neutral value or a pass.
Source identities come from the existing immutable Git inventory owner. Archive
text must reproduce each inventoried blob hash before it can supply a setting.

Verifier options resolve native interface getters through JAXB field names,
native default initializers and the independently recorded consumed XML.
Profile selection follows pinned loader/entity flags and verifier dispatch,
including support-vehicle precedence and inherited aerospace flags. Technology
settings follow native MTF/BLK switches and TechConstants; BLK's IS/year exception
is retained. The game year comes from the native verifier initializer.

The goal's four pins remain explicit. MekHQ is non-consumed research context,
not a loaded runtime or compatibility claim. Native build manifests, the portable
toolchain, exporter/helper source bytes and documented invocation supply runtime,
crew/network and BV override expectations. The full Java version string is
captured independently from the selected portable toolchain, not an oracle row.

The historical LF XML hash and the consumed CRLF XML hash remain distinct exact
identities. Text normalization explains their relation; trust checks use the
consumed byte digest. The actual provenance sidecar remains separate from the
expected policy and must be bound to the exact reference bytes.

The full-cohort proof must independently assert `ok: true` and zero violations
for all 9,815 units. A report-only CLI success is insufficient. It proves trust
adoption for the recorded full cohort, not construction/BV term parity or row
3.4 completion. Blocking activation is P6's later explicit invocation flag after
the approved policy lands. P8 alone updates task state and retains unspecifieds.
