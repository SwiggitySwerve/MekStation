**APPROVE-WITH-NOTES.** No blocker. One new major (M2) that is a design-level cost for Task 14, not a defect in this slice: the host fold is component-local and resets per binding, while `connectStoredCampaignSyncTransport` reuses the match's live transport, so any rebind without a reconnect (route navigation between the three host-mounting pages, a StrictMode remount, a `roomCode` change) starts a binding from EMPTY on an already-hydrated connection. Cursor -1 versus CF3's literal 0 (author deviation): correct. The server frames every baseline at `sequence: -1` (`bindCampaignSyncConnection.ts` 1859, `CampaignSyncSession.ts` 932) and the log hands out sequences from 0 (`campaignHostBatchCommit.ts` 112 `sequence = await host.nextSequence()`, healed logs start at `nextSequence: 0`; the mirror store's own doc says "the following log events (sequence 0+)"). `foldCampaignEvent` refuses `event.sequence <= fold.lastSequence`, so a baseline adopted at 0 would refuse a first live event at 0 and the consumer would report `fold-rejected`, which the transport turns into `recover('application-failed')` and a rejoin loop on a fresh campaign. ## 5. M1 handling and recovery semantics

- The author's placement is right. `handleApplicationRefusal` in the P2CF1 transport calls `recover('application-refused')` (view torn down, `failed = true`, `pending` cleared) before any `onError` listener runs, so the consumer cannot "ignore a superseded unknown-receipt"; option (a) can only live in `campaignSyncTransport.ts`, a P2CF1 leaf outside `restrictions.P2CF2`. Editing it would have been an unregistered leaf. CF7 stands as the Task 14 precondition.
- "One rejoin per occurrence": `rejoin()` is idempotent per binding (`live` flag), closes the transport, and bumps `rejoins` so both effects re-run; the host resets its fold, the guest's next baseline replaces. Each M1 hit therefore costs one close + fresh join + replacement baseline; durable state is unaffected (cumulative commit already covers the refused receipt). Safe but not free; the frequency at Task 14 is why CF7 is hard.
- Unlimited rejoins: each cycle needs a server refusal or close, so there is no tight loop; a server that refuses every join would cause a reconnect per refusal. CF8 (bounds) stands.
- Rejoin closes the shared transport: `transport.close()` deletes it from `activeTransports`; the entry panel and the launch page keep references to the closed instance. Unreachable before Task 14 binds creators; new carry-forward CF10.
- `confirmApplied` throwing stops the queue without a rejoin (author concern 1): confirmed by probe P4 (baseline confirm throws -> no ACK, no refresh for the next offer, `rejoins` 0, jest reports the rejection). Nothing in the shipped transport throws there (send failures are caught inside `drain`), so fail-closed today; m9.
- Socket close with no offer in flight: confirmed invisible (probe P7, `rejoins` 0 after `onclose`). The transport's `onclose` sets `closed` and clears `pending` but emits nothing; the consumer learns only through a `refused: closed` confirm result or an INTERNAL_ERROR frame. Transport leaf; CF12.

## 8. Findings

Blockers: none.

Majors:

- **M2 (new; design-level, Task 14 cost, not a P2CF2 deviation). Rebind on a live transport starts from EMPTY.** `connectStoredCampaignSyncTransport` returns the match's active transport when one exists (lines 495-505); the surface's cleanup never closes it; the host fold is a `useRef` of this component and is now reset on every effect run. So every binding that is not the first on a connection (route navigation between `CampaignDashboardPage.tsx` 354, `personnel.tsx` 107 and `campaignPageShell.tsx` 358, a StrictMode remount, a `roomCode`-only change) binds an EMPTY fold with `latched = false` to an already-hydrated connection that will send no new baseline. In receipt mode the next linked offer fails the adjunct check and forces a rejoin (P1): correct state, one reconnect per navigation. In legacy mode the next event seeds the fold from empty (pre-existing for a fresh mount; new for a `roomCode`-only change, which no client code performs today: `coopSession.roomCode` is written only at creation in `CampaignCoopEntryPanel.tsx` 258/333). The registered proof ("starts every host binding from an empty fold...") installs a mock `connectStoredCampaignSyncTransport` that records a new connect per call, so it demonstrates the reset but not production's reuse. My CF1 wording ("before the new transport opens") assumed a reconnect per rebind; I correct it in section 9. Owner decision before Task 14 activation (CF11): hold the host fold in a module-scoped store as the guest mirror is, or close the transport in the surface cleanup so each binding gets its own hydration, or accept one rejoin per navigation; in every case keep the adjunct check, which is what makes the path fail closed.
