## Five-class analysis

- **Authority.** Membership precedes policy on all four surfaces (admitSocket, publishEvent per recipient, sendReplay/handleSessionJoin, legacy callback with durable re-verification). Host, GM-without-seat, spectator and same-side players receive the same refusal: no privilege is a fog exemption. Non-members' bytes are unchanged from Main apart from the physical close code. The server stays authoritative: clients cannot influence the decision (it reads only the store).
- **Privacy.** Fog-on/unknown private reads refuse before any baseline, event, replay chunk, LobbyUpdated or delivery number with a fixed, secret-free reason; the frames carry only matchId/ts/code/reason (pinned by the no-unit-reference regex). Unreadable config is distinguished from unknown config without permitting delivery. Residuals are F4 (raw hook, standing), F5 (channel broadcast, pre-existing), and the out-of-manifest HTTP/lobby items already carried forward.
- **Replay.** No event, journal, reducer or cursor-persistence change. Refused frames are never numbered (R3), so a reconnecting viewer's delivery sequence stays gapless and the from-cursor resume still owes the withheld frame (pinned for the actor's own declaration). stampReplayDeliveries is unchanged. Rewind ceiling handling is untouched.
- **Idempotency.** Every refusal is read-only: no delivery assigned, no ack, no epoch, no audit or outbox write, no match row update. refuseFogSocket swallows send/close errors and detach is idempotent, so a second publish against an already-refused socket is a no-op (pinned: send called once across two broadcasts).
- **Concurrency.** attachedSockets() is a snapshot, so detaching during the fan-out loop is safe. Config is immutable after creation (no update route), so the two reads in a fog-on admission or the config-then-seat reads in the legacy path cannot straddle a toggle; a seat revocation between them only tightens. Two concurrent publishEvents against the same fog-on socket both refuse; ws ignores close() on a CLOSING socket and the second send throws into the catch.
