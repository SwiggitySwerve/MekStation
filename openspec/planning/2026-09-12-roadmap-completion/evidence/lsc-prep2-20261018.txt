## What changed from the prototype (design decisions)

1. **token.ts is not touched.** Seat mint is `POST /api/multiplayer/auth/local-seats {action:'mint'}` and goes through `LocalSeatCredentialService`. The primary vault mint stays byte-identical. This drops `token.ts` and `localSeatToken.test.ts` from LSC-1, which avoids the U101/U101a literal claim on token.ts. `coopCampaignAuthTokenStore.ts` is also unchanged and drops from LSC-2, which avoids the U101c literal claim. Seat bearers go into the existing per-match session store, so every existing consumer (launch, transport, share panel, route surface) keeps working without edits.
2. **Schema (LSC-1DB, migration v33 = head+1 at 1b8558625).** There are two tables:
   - `local_seat_credentials`: seat ids restricted by CHECK to `local-seat-1` and `local-seat-2`; encrypted private key; generation as the fence; `revoked_at`; durable `failed_attempts` and `locked_until_ms`.
   - `local_seat_credential_operations`: one row per operation id, with seat, kind, fingerprint and result generation. This gives real replay, which the prototype's single column could not.
   
   There is no lazy CREATE TABLE. Everything goes through the transactional catalog.
3. **Repository writes** are a single `BEGIN IMMEDIATE` transaction:
   - An operation id that matches an existing one replays. A reused id with a different kind, seat or fingerprint is refused.
   - Then a compare-and-set on the generation.
   - Then the operation row is recorded.
   
   Revoke on an already-revoked seat is a conflict. Re-provision clears revocation and lockout. Failure counting is fenced by generation.
4. **Service.**
   - Every operator write verifies the primary vault password through `unlockIdentity`. It never calls `setActive`.
   - Throttles: a route-wide mint window (10/min) and an operator window (5/min), both checked before any KDF; one in-flight mint per seat; durable lockout after 5 failures, for 60 s.
   - The generation fence is re-checked after the KDF and again after signing.
   - Seat tokens are ordinary unscoped tokens with a default and maximum lifetime of 1 h.
   - The fingerprint deliberately excludes passwords. A retry with a changed password is therefore fenced by generation, and the UI generates a fresh operation id on every click.
5. **Route guard.**
   - The Host must be loopback (`127.0.0.1`, `localhost` or `[::1]`), which blocks DNS rebinding.
   - `Sec-Fetch-Site` must be same-origin or none, and `Origin`, if present, must equal Host. The guard runs before the body or any KDF.
   - `Cache-Control: no-store` plus `applySecurityHeaders`.
   - Errors: 400 detail-free; 401 `LOCAL_SEAT_DENIED` or `OPERATOR_DENIED`; 409 `OPERATOR_IDENTITY_REQUIRED`, `GENERATION_CONFLICT` (with currentGeneration) or `OPERATION_MISMATCH`; 429 with Retry-After; generic 500.
6. **UI.**
   - `LocalSeatCredentialPanel` is mounted in CampaignCoopEntryPanel. It holds the per-profile choice (localStorage, public value only), the trust disclosure, and the operator provision/re-provision/revoke form. Passwords are cleared after every submit. It makes no request on mount, so existing tests are undisturbed.
   - Join uses the seat mint only when a seat is chosen. Host create stays on the primary vault.
   - `CoopCredentialRenewal` handles both primary and seat credentials. It warns 10 min before expiry and shows when the bearer has expired. It re-mints with the same choice, refuses a different playerId, and reloads only if no transport is live.
7. **Mount point finding.** `CampaignPageFrame` (campaignPageShell) does **not** render on the dashboard (where a guest lands after joining), missions, launch, starmap, log or personnel. `CampaignNavigation` renders on every one of those and already receives `coopSession`. That makes it the single correct seam. It is a new leaf (src/components/campaign; claimed by R7.context and R8.starmap through directory aliases, both planned), and campaignPageShell is not needed.

## Findings worth Root's attention

- **F1 (pre-existing, outside LSC).** `clientRateLimitKey` trusts `X-Forwarded-For`. Any loopback caller can rotate that header and slip past the per-client KDF limiters on token.ts and vault unlock. LSC's limits are route-global and don't rely on it. Carry forward to U101/B15.
- **F2 (pre-existing).** No auth route has a Host/Origin (CSRF or DNS-rebinding) guard. LSC adds one only on local-seats. Carry forward to B15/U101.
- **F3 (pre-existing, affects the v2.2.0 session).** The co-op path has no expired-token recovery at all, and the GM's primary bearer defaults to 1 h. Today, any session longer than an hour loses reconnect and launch for the GM as well as the guests. LSC-2's renewal banner covers both, which matches the registered "three identities ... expired-token recovery" requirement.
- **F4.** Migration head pins: R6 in `SQLiteService.replayCheckpointsBranch.migration.test.ts` (`{version: 32}`) and the applied-view reapply test in `SQLiteService.migrations.test.ts` (deletes version 32 and expects it to re-run). Both break as soon as any migration 33 lands. The fixes are one line each: pin 33, and `>= 32`. Any other lane that adds a migration first will collide, so re-allocate the version at admission.
- **F5 (owner-visible trade-offs; Root recommendations, not owner answers).**
  - Re-provision rotates the key and therefore the playerId. A guest who forgets a password comes back as a new principal and the GM has to admit them again. I rejected key escrow.
  - Seat bearers are capped at 1 h, versus 6 h for the vault, to bound how long revocation takes to bite. In long sessions guests re-enter their password about once an hour.
  - A same-host caller can lock a seat or exhaust a window for up to 60 s. That is accepted under the trust model.
  - GET returns public seat metadata (labels, playerIds, lockout) to any loopback caller.
- **F6.** Out of the box, RED fails at module resolution for any unit whose tests import new modules. LSC-1DB's test looks the migration up by name, so its RED is behavioural (below). I recommend the same lookup pattern for LSC-1S, LSC-1 and both LSC-2 units at admission.
- **F7.** The in-flight mint guard is per process. That is fine for the single custom server, but it would need DB-level serialization if the server ever ran multiple workers.
- **CF-S-8.** LSC adds no reseat-to-spectator path. Choosing a local seat never touches match seats or side assignments; D14 states this and keeps S's R1/R4 rows as the anchors. CF-S-8 stays with I1–I4.

## LSC-2P packaged-browser proof plan (unrun)

1. **Preconditions.**
   - Every source predecessor is closed on exact Main.
   - The installer is built from that Main. Record the installer and executable SHA256, version, executable path and PID, the private userData/DB path, and the owner of the 127.0.0.1:3001 listener.
   - Gate each automated phase on the idle check. If the packaged server's PID makes the gate busy, wait or ask for an explicit run instruction.
2. **Profiles.** Use three Chrome instances with separate `--user-data-dir`, each with its own debugging port, launched once and **left open for the whole proof**. sessionStorage holds the bearers and does not survive a browser restart. Each phase attaches with `chromium.connectOverCDP`. The dedicated config has no webServer and no globalSetup, uses 1 worker, keeps the default 30 s timeout per test, and baseURL is `http://127.0.0.1:3001`. No E2E routes, seeding, storage injection or TTL override.
3. **Phase A (T0).**
   - GM profile: create and unlock the primary identity in Settings, create the co-op campaign, then provision both seats through "Manage local seats".
   - Guest profiles: choose seat 1 or seat 2, then join through the room-code dialog.
   - Record three public playerIds, the campaign/session and the revision.
   - Prove a seat choice alone grants nothing until the GM admits the player through ordinary flow.
   - Reload and reconnect all three and check the IDs are the same.
4. **Phase B (T0 + 52 min).** The banner reads "expires soon". Renew P1 and the GM through the UI; their IDs stay the same.
5. **Phase C (T0 + 62 min).** P2's banner reads "expired". Recover with the password: same ID, and it reconnects.
6. **Phase D.**
   - Operator revokes seat 1 through the UI.
   - P1's next renewal is refused; record that the bearer issued at T0 + 52 min stays valid until it expires.
   - Re-provision with a new password. The old password fails. Re-claim gives a new ID, and the GM admits it.
   - Lockout: 5 wrong guesses, then 429 until 60 s have passed.
   - Screenshots and logs must not contain any secrets.
7. **Evidence.** A table of public IDs, session and revision per phase; artifact hashes; and real failures. All recorded in `docs/releases/v2.2.0-local-seat-proof.md`.

Waiting between phases happens outside any test, so no timeout is raised. P2, Task 18, U38 and the v2.2.0 human session stay held until both LSC-2 and LSC-2P are closed on exact Main.
