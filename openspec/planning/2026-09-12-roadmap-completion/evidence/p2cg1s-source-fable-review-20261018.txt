## Five-class analysis

**Authority.** The decision still lives in one place, the audience context consumed by \`MATCH_WIRE_PUBLICATION_BOUNDARY\` (ViewerPublicationBoundary.ts:147-152: sealed = revealed OR actor-owned). Seats come from the durable store (\`getMatchMeta\`) on each publication / replay, never from the client or the viewer brand. The viewer brand itself is re-validated per publish by membership epoch (AuthorizedViewer.ts:228-239; the epoch hashes seat occupancy, MatchSeatMembershipSource.ts:67-88), so a reseat invalidates the cached viewer on the next frame. Seated (human-kind) viewers are unaffected: \`isSpectatorPlayer\` is false, the gm shortcut and the side lookup run exactly as before (verified by the "human actor and a seated gm keep it" rows, fog on and off, all three declaration types, and by R3). The actor keeps their own declaration. No new authority surface, no client-resolvable path.

**Privacy.** Can any spectator path still receive an unrevealed sealed declaration or a payload-derived digest?
- Live (\`publishEvent\`): no — seats passed; sealed types bypass the fog filter (:303-306) but reach the guard with the seat-aware context; omit consumes no delivery number.
- Join replay / rejoin with cursors / isolation-cleared resume / rewind re-replay: all route through \`sendReplay(ctx, socket, fromSeq, playerId)\` (ServerMatchHost.ts:896, :992, :1474; bindMultiplayerSocketConnection.ts:287) -> \`sealedChoiceAudienceContext\` with seats; \`visibleThroughSequence = MAX_SAFE_INTEGER\` so only genuinely finalized declarations are revealed. Verified by the SessionJoin row, the reseat row and by R5.
- Reveal republish (\`broadcastEventInMode\` -> \`committedDeclarations\` -> \`publishEvent(..., true, reveal.sequence)\`): the committed row goes through the same seat-aware context; the spectator gets it exactly once with a contiguous delivery number (sealedChoiceDelivery rows, both brands).
- HTTP fog-on history/export: unchanged, already seat-first (\`!spectator && ...\`, FogAwareMatchProjection.ts:236-242); matchHistoryFog suite passes.
- HTTP fog-off: the parent \`ViewerProjectionService.isVisibleToViewer\` (ViewerProjectionService.ts:94-104) returns \`true\` for \`sealed-to-actor-until-revealed\` — no hold at all — but reads only \`ROOT_EVENT_BRANCH_ID\` (:239), which the S1 mirror does not write, so it is latent (documented at FogAwareMatchProjection.ts header "fog-off has no sealed-choice hold on this path yet"). Outside S's leaves; CF-S-1.
- Payload-derived digests: live/replay frames carry no \`expectedPostStateDigest\` (ViewerFrameProjector strips authority fields; the HTTP path sets it \`null\`). The B10 rows additionally assert the payload marker strings (\`"q":11,"r":-4\`, weapon id, limb) are absent from the raw \`socket.send\` strings, not just the event id.
- Raw no-\`playerId\` \`sendReplay\` and the P2P reconnect callback stay unguarded (pre-existing, U26); the production binder always passes the verified identity.

**Replay.** Live and replay agree for every row tested (same event ids, same committed payload on the reveal). The replay context reads \`meta.seats\` at replay time, so a from-zero replay after a reseat withholds what the viewer saw while seated (current seats govern; the reseat row asserts this). My scratch probe (scratch-reseat.log) confirms a reseated viewer's from-zero replay stamps are reused for frames it already held (\`evt-phase-2\`->0, \`evt-phase-4\`->2) and new numbers are assigned to the never-sent prefix (3,4) — the documented \`stampReplayDeliveries\` semantics, unchanged by S.

**Idempotency.** Withheld frames consume no delivery number (the omit \`continue\`s before \`admit\`/\`assign\`), which is exactly what lets the reveal republish in \`onlyUndelivered\` mode deliver the committed row once and keep the viewer's sequence gapless. R7 shows the dependency is real: consuming a number at withhold time silently loses the reveal (recoverable only by rejoin). The outbox drain (\`broadcastUndeliveredEvent\`) uses the same path. Nothing in S changes numbering.

**Concurrency.** \`publishEvent\` performs two store reads per frame (viewer resolution via the membership source; \`getMatchMeta\` for state/seats). A seat change landing between them would pair a viewer from one epoch with seats from the next for one frame. Both directions are safe for this rule: newer seats (now spectator) withhold; older seats (still playing) fall through to the side lookup, which is the pre-S behaviour for a seated player. In-process stores make the window negligible, and there is no product path that reseats a playing principal to spectator mid-match (\`addSpectatorSeat\` rejects a playing conflict, spectatorSeats.ts:118-126; the spectate route only appends). Per-player viewer cache is per-frame (\`viewerCache\`), so a reseat cannot persist a stale decision across frames (author's M10 covers caching seats; my R1 covers the stale \`participantId\` the cached viewer carries).

## GM-branded spectator (ruling S-PREP-P1) and L1

The change: a gm-branded viewer occupying a current spectator seat (the co-op campaign host seated via \`defaultSeatsWithSpectatorHost\`, matches/index.ts:178-190, with a campaign-session \`gm\` row, MatchSeatMembershipSource.ts:108-128) used to receive sealed declarations pre-reveal on live and replay (the \`role === 'gm'\` shortcut); it now receives them only once revealed. Assessment: correct. (a) The registered B10 contract says "even with a stale sideAssignments entry or a gm-branded viewer"; (b) fog D6 says a spectator seat owns no side; (c) HTTP already behaved this way, so the surfaces now agree; (d) a non-spectating gm keeps pre-reveal visibility (rows + R3). GM campaign arbitration (\`CampaignGmArbiter\`) consumes campaign proposals, not tactical sealed choices, so no GM function depends on pre-reveal tactical visibility.

L1 (two deploying players + non-playing GM): verified in code. \`coopMissionCreate.ts:272-305\` builds mission meta with \`sideAssignments\` (both on \`player\`), \`coopMission\`, and **neither \`seats\` nor \`coopCampaign\`**. Therefore \`meta.seats ?? []\` is empty (\`isSpectatorPlayer\` false for everyone) and \`deriveMembershipRole\` returns \`player\` (no \`coopCampaign.campaignId\`), so nothing in S fires there. The e2e GM packs (\`gm-two-player-privacy.pack.spec.ts\`, \`gm-two-player-lifecycle.pack.spec.ts\`) assert the opponent's wire only and state that the tactical channel mints no gm viewer; \`gmNoPromotion\` asserts pause/no-HostMigrated only. Unaffected.
