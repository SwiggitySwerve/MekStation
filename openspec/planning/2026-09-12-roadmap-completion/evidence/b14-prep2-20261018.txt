## Council-3 wording applied

`src/lib/multiplayer/server/fogMatchAdmission.ts` now contains one capability predicate. Callers use it instead of scattered config checks.

- `noPerViewerRevealProjection(config)` is documented as "no per-viewer reveal projection available for this match". It returns true when config is unknown (`undefined`) or `fogOfWar === true`. A known config that omits the flag counts as fog-off.
- `matchLacksRevealProjection(store, matchId)` reads authoritative config. An unreadable config counts as unknown and returns true.
- `FOG_REFUSAL = 'fog-projection-unavailable'` and `refuseFogSocket` send the existing `Close`/`AUTH_REJECTED` vocabulary and physically close with 1008. The close happens even if the send throws. No protocol enum was added.
- Every surface calls the predicate: admission (`ServerMatchHost.admitSocket`), live publish (`ServerMatchHostEvents`), replay/join/direct/no-player replay and the legacy reconnect callback (`ServerMatchHostReplay`), metadata GET (`[id].ts`), export/private-preview (`FogAwareMatchProjectionService`), and in B14-HEAD the `/head` route.
- The spec delta is now `### Requirement: Fog-On Private Reads Require a Per-Viewer Projection` and contains the mandated sentence verbatim: "Fog-on private reads SHALL be served only through a per-viewer projection; when none is available, refuse with fog-projection-unavailable." It has three scenarios: member fog-on/unknown -> refuse + 1008 + detach; known-off without projection metadata -> no fog refusal; non-member -> generic refusal only. The prototype used the wrong heading levels; this corrects them. `openspec validate fog-of-war --strict` passes.
- No test pins GameCreated as a public full-roster event. The deleted Main export test, which asserted that `createdUnits` were public, is not re-added. The digest census reads the stored envelope only.

### Changes from the prototype besides the wording

1. **Fog-off legacy reconnect preserved.** The prototype verified durable membership for every metadata peer in both fog states. That broke the fog-off test `ServerMatchHost.test.ts` "answers original guest reconnect-request". Now membership is checked only on the path that would refuse for fog. A current member gets `fog-projection-unavailable`; a stale peer gets the generic `Match in progress`. Fog-off goes to `answerReconnectRequest` unchanged. The clumsy aliased double import is gone.
2. **Export service keeps fog-off byte-identical to its parent.** The prototype added a new seat lookup to fog-off match reads. Now config is read first, which Main already did for every match stream. Only when the predicate refuses does the service run `requireCurrentSeat`: scope check, then durable seat. A missing seat gives `wrong-session` "Authorization refused"; a seat-lookup failure gives the constant `projection-failed`. Neither carries fog detail.
3. Tests: the copied spectator header and mojibake were fixed (ASCII only, no BOM) and the describe was renamed from "scratch". New cases cover fog-on same-side players, unknown config at live publish, and join/replay server-side detach while the transport still reports OPEN. Metadata now has a fog-on **stranger -> 404, no fog** row. Export has **no seat / seat failure -> no fog**. Imports misplaced above file headers were restored, and an unused import was removed.
4. The census test is retitled "mirrored journal event digest changes with hidden payload or post-state digest alone". It stays in B14-0's `matchHistoryFog.test.ts` as the characterization that backs both export and head refusal. B14-HEAD's red proof cites it.
