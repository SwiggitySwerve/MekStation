## 6. Decision points

**(a) GREEN committed with `--no-verify`.** Acceptable as a hook bypass; not acceptable as a precedent without a ruling on counting. Facts: lint-staged runs `oxfmt --write` on staged `*.ts` by explicit path, which overrides `.oxfmtignore`'s `scripts` entry (I reproduced: `oxfmt --check scripts/release/l1-built-server-fixtures.ts` reports issues; the formatted file is 102 lines). CI Format Check honours the ignore and passed; CI Lint and Type Check never visit the leaves; the hook's `npm run typecheck` would not have covered them either. So no CI-equivalent gate was dodged, the bypass is disclosed in the PR body and the receipt, and `.oxfmtignore` itself says the repo does not format scripts. The hook and CI disagree on `scripts/*.ts`; that is a maintenance defect (CF-SMOKEA1-6), not this unit's. The cap-gaming risk is real but is M3, not the bypass: with or without the hook, 1264 formatted lines sit under a 500 cap by density. Ruling: accept the bypass for A1; require Root to rule before A2 admission whether counted lines for the smoke lane are physical or oxfmt-normalized (CF-SMOKEA1-3). If Root rules "normalized", A1 is already merged under the old rule and is not re-litigated; A2/B must split.

**(b) M13 and M19.** Fix in-PR, together with the gaps in section 4, as one tests-only amendment commit after GREEN, recorded in the local receipt as a RED amendment (mutant survives before, is killed after; 15 -> N/N green). Rationale: A2 and B are contractually forbidden from editing A1 leaves, so "carry forward to A2" means "never, unless a new unit is registered"; the test leaf is line-exempt; and the amendment does not change the implementation leaves' bytes unless A2 (below) is taken, so the real-run receipt stays valid for the implementation hashes. RED discipline is preserved by recording that the amendment is a falsifier-of-the-falsifier (its RED is the surviving mutant, not a product failure).

**(c) Explicit-path lint under a gitignored `scripts/**`.** Sufficient as proof for this head (I re-ran it: 0/0 on 4 files), consistent with the established force-add convention (606 ignored-but-tracked script files) and with the zero-headroom lint-units ceiling (50/50 unchanged, so the leaves neither consume nor game it). Not sufficient as a durable gate (L3): nothing in CI will ever lint, format, typecheck or run these leaves. A2's and B's registered harness selectors run A1's test leaf, which keeps it alive through the lane. Whitelisting `scripts/release/` in `.gitignore` and adding the leaves to lint-units would be an out-of-manifest edit and needs the ceiling raised or headroom found - CF-SMOKEA1-4 for a maintenance unit, not for A1.

**(d) The stand-in server is harness-only.** Confirmed. The stub is a string inside the test leaf (`stubSource()`), written into throwaway git repos under `os.tmpdir()` by `stubRepo()` and reached only via `runHarness({ repoRoot: fixture.repo, ... })`.
