## 3. Five-class analysis

**Authority.** The client gains no authority. The guest join reads campaign identity from the server through the verified identity mode and still submits a CampaignJoin that the WS layer gates (seat/revocation unchanged; auth.ts, token.ts, Player.ts untouched). The entry panel validates matchId/campaignId/status before any socket and refuses 400/401/404 finally (E10 rows; no anonymous fallback; exactly one invites request). The launch page never closes a transport it did not create and sends only through a transport bound to its own seat (RV9 caught). The surface refuses a stored transport bound to another campaign on the same match (CF-H16 rows; MSu1/MSu2 and RV9 caught). Bound/unbound join bytes and the numeric legacy ACK are identical before any offer (pinned), so nothing is activated on the wire.

**Privacy.** Bearer only in the Authorization header, URL exactly ?campaignIdentity=1, cache:'no-store' (E1 row; ME5 caught). No token= anywhere (asserted on every refusal row). No /api/multiplayer/matches/ read (asserted). The resolved campaignId is used for the mirror and the guest campaign; the identity response's layout/status are not stored. The only disclosure in play is G2A's recorded PRIV-1 correlation (campaignId to anyone with a live code and a self-signed bearer), which G2 neither widens nor narrows; it stays a B15 obligation (R-PRIV-1). Error strings shown to the user are the route's constant bodies.

**Replay.** The guest adopts only the first snapshot whose event.campaignId AND payload.state.campaignId equal the identity-resolved id (MS4 and both "another campaign" rows; a mismatch rejects without touching the mirror). The transport's legacy path forwards every campaign frame regardless of campaignId (unchanged from base), so post-adoption filtering of foreign legacy events rests on campaignMirrorStore (applySnapshot/applyEvent refuse a different campaignId once set, lines 265/306) and on the host fold/consumer, which G2 does not own. Snapshot-at-revision-0 semantics are unchanged (applySnapshot(snapshot, 0)). A replacement B's listener is attached only after A's is detached, so a late A frame publishes nothing (pinned). CF-H6 is genuinely pinned: a bound host against a legacy server keeps one socket across remount at 2T, and my re-run of the consumer mutant RM-G9 fails exactly that row (1/129).

**Idempotency.** Same-object registration is a no-op without notification (MT3 caught). releaseActiveTransport is identity-guarded so a late A.close() never drops B (MT2 and the stale-timeout row). settle() in the seat wait is re-entrant safe (second call clears nothing new, stopFollowing is idempotent, resolve/reject no-ops). unsubscribe deletes a per-subscription wrapper (RV5 caught). The replacement resend is sent once per seating (ML3 caught, "exactly once" row). _resetCampaignSyncTransportsForTest clears observers (MT6 caught).

**Concurrency / reseat races.** I traced each ordering against the seat module:
- Seat replaced between snapshot and adoption: the wait resolves on A's frame, the foreign takeover lands, the post-await boundCampaignSyncTransport(seat) check refuses (row pinned; RV12 caught: a weaker "any active transport" check adopts).
- Same-seat replacement B during the wait: subscribe-then-reconcile follows to B, snapshot heard on B completes the join with no render (pinned). A is left open (note N3).
- Foreign replacement during the wait: the follower detaches from A, seats nothing, the one fixed 10 s timeout rejects, A is closed, the foreign socket is neither adopted nor closed (pinned).
- Unmount mid-join: the per-attempt AbortController rejects the wait, the catch closes A and returns without setState (pinned; ME4 caught).
- Reentrant registry change inside an observer: observers are snapshotted and isolated (MT4/MT5 caught); reconcile re-reads the getter and is idempotent on next === seated; the attach-time reentrancy guard (seated !== next -> off()) is correct but unpinned (RV4 survived).
- Server-initiated close: onclose releases the slot only if it is still the active object and notifies followers (RV6 caught by the CF12 row).
- Registration order: setActiveTransport is the last statement of connectCampaignSyncTransport, after every socket handler is installed, so an observer never sees a half-built transport.
- Cross-campaign binding on the same match: connectStoredCampaignSyncTransport refuses by campaignId (pre-existing G1 logic, now reachable because both surface creators pass expectedCampaignId); boundCampaignSyncTransport additionally checks playerId and role for the launch/entry seats. The stored connect itself still checks only campaignId, not role/playerId (pre-existing; note N5).
