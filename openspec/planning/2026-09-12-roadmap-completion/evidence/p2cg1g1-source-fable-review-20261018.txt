## 5. Per-class findings

- **Authority.** The fold cell is cached view state; receipts remain the transport's. A continued lineage cannot certify more than it applied: the disposed binding never confirms (settle returns on `!live` after its await), the remount confirms only what it folded, and the transport withholds any ACK behind an unapplied pending offer (C3, PROBE-A `acks [v1-r0]`). A replacement transport cannot inherit a stale lineage (RM-G2 caught), another campaign cannot read the first campaign's facts (C2), and a fresh cell is a new object the old binding's `fold` reference does not point at. `refusalFromFrame` keeps application errors out of the refusal posture (RM-G8 caught). The direction of every residual is safe-side: ACKs are withheld, never advanced.
- **Privacy.** Nothing new reaches the wire: the host join still quotes -1 (omitted), the store serialises nothing, the heard map holds integers keyed by transport identity (WeakMap, GC-bound; RM-G6 shows string keying would leak the mark across transports on one match). The re-projection writes only the local campaign store.
- **Replay.** Offers still settle in receipt order on one queue; `foldCampaignEvent` rejects `sequence <= lastSequence` but accepts a gap, so a lineage that missed frames during a gap folds the next offer over an incomplete state (CF-H3) while the transport's prefix discipline keeps the ACK withheld. The heard mark is recorded at consume, before the step completes, so a consumed-but-unconfirmed offer leaves the record equal to the cursor and the remount skips the window (CF-H1). The single-slot store and the per-transport heard mark are keyed differently, so a lineage that never folded a frame can skip the window (CF-H2; PROBE-B). A duplicate or lower-sequence frame during a gap moves neither `lastSeq` nor the record, which is consistent (the fold would have rejected it).
- **Idempotency.** `claimCampaignHostFold` is idempotent for the same binding (same cell, `continued` true, re-projection is a pure overwrite); StrictMode double effects claim, dispose, claim and arm one window. `heard()`/`dispose`/`rejoin` keep F's once-only guards (CF-G8 pins the timer trade). RM-G4 survived: the store mirrors the consumer's `active` predicate by hand; if either side changes, they drift silently.
- **Concurrency.** `held` is mutated synchronously inside the effect; the consumer writes `binding.fold.current` only in the synchronous part of `settle` before its await, so a dispose (React cleanup, a separate task) cannot interleave with that write; after the await only reads happen. The transport sets `lastSeq` before dispatch and `consume` runs inside that dispatch, so the record is exact. Liveness: a rebind on a heard transport arms no window, so the only recovery paths for a cut settle are the server's own view failure (none timed; the server never waits for an ACK, it just keeps publishing), the transport's confirmation timer (armed only after an ACK is sent, which the withheld prefix prevents), `pending-overflow` at 64 offers, or a reload. The store holds a strong reference to the last transport (one object, replaced at the next host claim); the heard map holds none.
## 6. Judgments on the open points

1. **Retained fold re-shown at remount (accept, with a guard).** Projecting the continued fold at bind is the right symmetry with the guest (`projectMirrorToCampaign()` at bind) and is what makes R2 observable; without it the dashboard would show the reloaded record until the next frame. It is safe when the lineage is current. It is wrong when the lineage missed frames during the gap: `continues` does not compare `cell.current.lastSequence` with `transport.lastSeq()`, so a lineage behind the cursor is continued, re-shown (stale balance), and then folds the next offer over the gap; the window re-arms (the gap row pins that) and ends it within T, and the ACK stays withheld, so nothing is certified. Accept the design; add the cursor equality to `continues` (or skip the re-projection when behind) when the store next opens (CF-H3).
2. **Heard semantics (sound choice; wrong moment).** The cursor-watermark refinement is strictly better than the stop-report WeakSet (the author's M1 and my RM-G5 show the second gap row discriminates), and the two gap rows pin exactly what #2236 review note 2 asked. For a legacy frame those coincide; for an offer they do not, and an unmount between consume and confirm leaves a record that says "heard" for an offer nobody confirmed. F had no such state because every bind started from EMPTY and armed a window. The fix is local to the consumer (record non-offers at consume, offers after a successful `confirm`, using the cursor captured at consume), passes all 100 registered cases and my probes, and keeps the legacy-server behaviour the amendment wanted. It is a consumer-leaf change, which G1 owns only for CF-G3; the lane is closing, so it is carried as CF-H1 with activation as the deadline. If the owner prefers it inside G1, it must land as a new red-first commit pair and be re-reviewed on the new head.
3. **CF-G3 (satisfied as registered, see item 2 for the residue).** W1 passes and the amendment's wording (a rebind on a transport that already delivered a campaign frame arms no new window; replacement transports keep their own) is delivered; the "already delivered" semantics are the narrower ones the admission receipt records, which is the conservative reading.
