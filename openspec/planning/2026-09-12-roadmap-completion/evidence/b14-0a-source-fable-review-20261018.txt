## Judged items

**(a) Helper in the RED commit.** Confirmed dead code at RED: no product file imports `fogMatchAdmission.ts` at f402759d4 and both product leaves are byte-identical to the base, so product behaviour is unchanged and all 11 RED failures are genuine behavioural failures. The author's justification is correct for the canonical seam as registered: the factory spreads `jest.requireActual(...)`, which throws at factory evaluation if the module does not exist (`{virtual:true}` would only help a factory that does not requireActual). Ruling B14-0A-R1 is recorded in the admission receipt before the RED commit. Acceptable ledger discipline; the stricter convention "RED adds no product bytes" is knowingly bent with a recorded ruling and a dead-code proof. Recommend future splits register the helper in the admission commit instead (it is behaviour-free) so RED stays test-only.

**(b) Ordering.**
- Metadata (`src/pages/api/multiplayer/matches/[id].ts:99-104`): authenticate -> getMatchMeta -> participant (host or occupied human seat) -> fog predicate -> serialize. Non-participants and spectators get the pre-existing generic 404 body; the fog branch is unreachable before the participant check. Reads and status codes for a stranger are identical to Main (same single store read), so no timing or body oracle is added. Known-off and flag-omitted: identical bytes (`{ meta }`), pinned by the retained multiplayerMatchMeta rows.
- History chain: `ViewerHistoryService.exportForViewer` resolves the viewer through `authorizeHumanAction` (durable seats; `HostAsGmMembershipSource` still requires an inner seat row) before `projection.project`; `FogAwareMatchProjectionService.projectWithIdentities` (`FogAwareMatchProjection.ts:275-286`) reads config, and on refusal verifies brand+scope and the durable current seat, then throws `projection-failed` / `fog-projection-unavailable` before `super.projectWithIdentities` (the only journal reader), before `auditRepo.readBySession`, before `collectPrivateExportViews`, and before the export route's `readMatchHistoryLineage`. History pages (`projectWithCursor`) call `projectWithIdentities` before `resolveEpoch`/`assignSequences`, so no epoch is minted on refusal. No raw fallback exists: `matchConfig` maps any read failure to `undefined`, which the predicate refuses; the `heads` projection-metadata dependency is no longer read at all, so an unavailable effective head cannot refuse a known-off match (pinned at matchHistoryFog.test.ts:634).
- One ordering nuance at the service level only (F3): config is read before the brand/scope check that the parent performs first, and an unbranded viewer is answered `wrong-session` on fog-on versus `not-a-viewer` on fog-off. Unreachable through any HTTP route (every caller brand-checks first) and not a non-member disclosure, but it is a service-level fog oracle for a future direct caller. Low.

**(c) Seam.** `jest.mock` module factories exist only in the four allowlisted test files (git diff confirms 10 added lines each, no assertion changes); nothing in product code or configuration references the override, so it cannot reach a production bundle. The allowlist guard (matchHistoryFog.test.ts:697-770) is sound for what it inspects (jest.mock/doMock/unstable_mockModule/setMock with a literal path containing `fogMatchAdmission`, canonical comment, both overrides present, all four B14-0A seams present) but it is a tripwire, not a fence: my probe R9 (an unlisted suite using `jest.doMock('@/lib/multiplayer/server/' + 'fogMatchAdmission', ...)`) overrode the predicate while the guard passed; `jest.spyOn`, a `moduleNameMapper` entry or a mock of the consumer module would also evade it. Real refusal is pinned unmocked by securityBoundary, multiplayerMatchMeta and matchHistoryFog (none mocks the capability module; the guard would flag them if they did). The seam's `matchLacksRevealProjection: async () => false` is consistent with the #2263 binding ("false means projection available") and with `noPerViewerRevealProjection: () => false`.

**(d) 1011/false semantics for B14-0.** Preserved: B14-0A exports only `FOG_REFUSAL` and the boolean predicate; no WS module imports it; `ServerMatchHost*.ts`, `MatchWireSealedChoices.ts`, `server.js` are byte-identical to the frozen controls (admission receipt hashes). The seam pins `matchLacksRevealProjection` as **async** returning `false`; B14-0 must implement it as a Promise-returning function and `await` it at every call site, otherwise the seam's Promise is truthy and the four suites would (loudly) refuse. Recorded as CF-B14A-5.

**(e) Completeness of HTTP private reads.** Contained: participant metadata GET; `/export`; `/private-preview` (projection throws before any private ref is exported or audited); history pages via `projectWithCursor` (no HTTP route currently calls `readHistory`, but the override covers it). Left open by design: `/head` (B14-HEAD; hidden-dependent digest, census row at matchHistoryFog.test.ts:499 consumed read-only); `/timeline` (audit rows + lineage; see CF-B14A-7 for the count/timing leak class); rewind-preview/commit (already refuse `fogOfWar === true`; an undefined config throws into the generic 500 before any projection; U26). Lobby/invite summaries (`joinableLobbies.ts:159,182`) publish `fogOfWar` for joinable lobbies to anyone, by design; the metadata route's non-disclosure therefore protects active/completed matches, not open lobbies (CF-B14A-8). `GET /api/matches/[id]` (post-battle report, unauthenticated) is the local combat-resolution surface, not a multiplayer journal read; out of B14 scope. Campaign routes read campaign streams only.

## Five-class analysis

- **Authority.** Membership precedes policy on both surfaces (metadata participant check; history resolver with durable seats, then the service's own seat re-check). Host/GM privilege is not a fog exemption (GM-without-seat refused 403; host private-preview refused 500). No new authority is granted to anyone; the only change for authorized viewers is refusal. Spectators remain non-participants of the metadata route.
- **Privacy.** Fog-on/unknown private reads refuse before serialization with a fixed, secret-free reason; refusal bodies pinned to exact shape. Non-members get the pre-existing generic refusals (404 metadata; 403 "Authorization refused" from the resolver) with no fog string. Residual channels are pre-existing and out of this manifest: `/head` digest (B14-HEAD), `/timeline` counts/timing (F9), lobby summaries publishing `fogOfWar` for open lobbies (F10/CF-8), WebSocket (B14-0).
- **Replay.** No event, journal, or reducer change; the fog-on effective-head read is removed with the served projection, and fog-off still reads the root branch exactly as Main (CF-S-1 untouched). No derived state is persisted or changed.
- **Idempotency.** Every refusal path is read-only: no epoch resolved, no sequences assigned, no private-access audit written, no match row updated. Repeated refusals are byte-identical.
- **Concurrency.** Fog config is immutable after creation (no update path) so the config-then-seat reads cannot straddle a toggle; the metadata route uses a single meta read. Seat revocation between the resolver and the service re-check only tightens (second check refuses). The unused per-request `SQLiteEventHistoryBranchStore` construction is wasteful but harmless.
