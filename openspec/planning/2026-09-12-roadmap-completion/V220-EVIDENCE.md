# V2.2.0 evidence contracts

`scripts/qc/v220-evidence.mjs` owns these required fields and refusal checks. These are evidence contracts, not acceptance records. Root verifies actual observations and human identity; a schema cannot authenticate an attestation. No gate is accepted by this document.

Every reference is `{ "path": "relative/file", "sha256": "64 lowercase hex" }`; absolute paths, drive paths and any `..` segment are rejected. Paths stay inside the bundle and hashes bind actual bytes; owner-page references must start with the planning directory. Closure references instead resolve against the tagged repository. Every record carries `inputSha256`, computed by `stepInputSha(plan, ledger, stepId)`: its step definition and only its relevant unit IDs, states and merge SHAs (all 46 prerequisite closure units for steps 7-9). Ordinary unrelated ledger or package edits do not stale a record. Every candidate record also carries `kind` and the same 40-hex `rcSha`. Names resolve through the checker's schema registry; unknown or misplaced names fail. `observations` is a nonempty array of `{timestamp, status: "PASS", description}` with ISO timestamps. Preserve failed attempts separately; acceptance contains their closed defects and successful retests.

## Step 2: local-seat-proof

Required fields: `kind: "local-seat-proof"`, `rcSha`, `inputSha256` (added by Root when the external bundle record is composed; it cannot exist before LSC-2P merges), `installer` (`filename` matching `MekStation-*-win-x64.exe`, `sha256`, `sizeBytes`, `authenticode`), `installed` (`exeSha256`, `productVersion`, `authorityUrl: "http://127.0.0.1:3001"`, `listener`, `freshAuthority: true`), `publicIdentities` (exactly three: `primary`, `seat1`, `seat2`, with distinct `pid_` ids), `scenarios` (S0-S7 each `PASS`, with timestamps and artifact names), `observations`, `artifacts` (filename-to-SHA256 map), `operator: {identity, kind, attestation}`, `gaps` and an empty `defects` array. The record also carries `reprovision` and `restart` observations; they are recorded, not asserted. It is produced by `docs/releases/v2.2.0-local-seat-proof.md` and binds a pre-RC installer; Step 8 must bind the RC bytes. Raw artifacts (traces, screenshots, the report) stay outside Git; only their SHA256 values are recorded.

## Step 7: closure-rewind

Required fields: `kind: "closure-rewind"`, `rcSha`, `closures`, `reruns`, `rewind`.

- `closures`: exactly one `{unit, reference}` for every checklist unit (currently 46). Reference the unit's existing `stageReceipts.mainProof.path`, prefixed with the planning directory. The checker reopens PASS receipts, compares merge identities, requires terminal ledger state and checks each merge is an ancestor of the candidate. Run the unchanged roadmap validator separately for its full historical receipt contract.
- `reruns`: references to JSON records `{rcSha, verdict: "PASS", argv, inputSha256}`. Bind each rerun to its own step inputs (3, 5 or 6). Cover every exact command registered in steps 3, 5 and 6: combined spectator proof, campaign journey, ownership proof and terminal P2J journey. Missing proofs must first be implemented by their owning units; baseline success alone never qualifies a release.
- `rewind`: `command`, `observations`, and separate `persisted`, `broadcast`, `replay` references witnessing real post-rewind dice production, capture and faithful replay on this RC.

## Step 8: two separate records

Both `installer-rehearsal` and `human-session` require `kind`, `rcSha`, `artifacts` (filename-to-SHA256 map), `operator: {identity, kind, attestation}`, `checklist` (a reference to `playtest/checklists/coop-uat.md` hashed against the candidate tree, so a session run on a stale checklist fails), `observations`, and `defects`. Each defect requires `id`, `status: "closed"`, and `retest: {timestamp, reference}`. An empty defects array explicitly records no defects. Use the existing session template and update the checklist's prerequisite gap after LSC qualification; this task changes neither historical checklist nor session evidence.

The human record additionally requires `operator.kind: "human"` and a nonempty `humanAttestation`. Label one human driving three seats accurately. An agent's rehearsal, even with identical artifact hashes and PASS observations, cannot satisfy this record. Both runs must attest installer smoke and the current three-seat checklist.

## Step 9: publication

Required fields: `kind: "publication"`, `rcSha`, `acceptedGates` (all eight checklist IDs exactly once), `artifacts`, `rehearsal` (reference to the installer record), and `releaseNotes` (reference whose path is `release-notes.md`). The notes must contain the exact `docs/releases/v2.2.0-topology.md` sentences the checker lists (loopback binding, no reverse proxy or tunnel, no remote play, HOSTNAME admission failure, unsupported Docker hosting) and both ledger quotes (multiplayer fog, same-server lobby visibility). The checker requires identical rehearsal, human-session and publication hashes, then hashes the actual files being uploaded. No rebuild can substitute for the rehearsed bytes. Record the resulting release URL and actual publication observation after publication; a preflight PASS alone does not complete step 9.

## Bundle and commands

An external Actions artifact named `v220-qualified` contains `evidence.json`, the four separate record JSON files, referenced proof files, `release-notes.md`, and `artifacts/` with exactly the files to publish, including `latest*.yml` and `.blockmap` update metadata, all hashed in the rehearsal record. `evidence.json` requires `rcSha`, `records` mapping the four kinds above to references, and `gates` mapping all eight checklist IDs to `{status: "accepted", reference}`. Root owns acceptance and provenance. The workflow downloads the explicit `qualification_run_id`, which must be a successful run of this repository on the tagged commit; the artifact lives outside Git so adding acceptance evidence does not move the candidate. The qualified-bundle producer belongs to later acceptance work; this task invents no acceptance or artifact.

Run `node scripts/qc/generate-v220-steps.mjs --gate-check --candidate-sha <tagged-commit> --evidence <bundle>/evidence.json --artifacts <bundle>/artifacts`. It refuses missing evidence and incomplete proofs, and prints `V2.2 GATE PASSED <sha>` only on success; release.yml requires that exact line, so a tagged tree whose checker ignores the flag cannot publish. `release.yml` checks out the tag, invokes this command and uploads those same files. Dispatch with `candidate_only: true` for private build artifacts. v2.2 container publication is withheld because that path rebuilds unqualified bytes; ordinary non-v2.2 releases retain their existing behavior.

For the owner page, optional `v220-step-evidence.json` contains `rcSha`, `steps` and `gates`; every step 7-9 record must name that `rcSha`; each `steps[id].inputSha256` uses that step's own digest, just like its schema records. Each complete step requires `state: "complete"`, `doneTest: "PASS"`, a hashed `reference`, and `records` mapping its evidence-schema names to references; gates require accepted status and references. `--check` reopens the appropriate schema records. Step 0's `step0-observation` record requires `timestamp`, `mainSha`, `pr2313.head`, and `lsc2c: {head, state: "local-verified", branch: "codex/lsc-2c-sol-20261020"}`. Local evidence cannot substitute for any unit's main closure.

Refresh observations with `--observe UNIT=BRANCH=ABSOLUTE_WORKTREE ...`; the timestamped overlay stays on stdout. Missing access, conflicting heads, or a worktree where the unit is still `planned` prints `UNKNOWN - DO NOT SELECT`. Root must reconcile it before admission. No committed snapshot reserves work.
