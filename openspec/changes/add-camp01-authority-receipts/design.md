## Context

The parent `add-saved-custom-unit-campaign-roster` change requires ten separately specified and implemented waves. Later waves must consume evidence from earlier exact reviewed commits and exact main, but the repository currently has no shared mechanism that proves command selection, toolchain inputs, GitHub provenance, artifact freshness, durable export, or cleanup identity.

This child owns only that verification seam. It must be implemented after all ten child OpenSpecs merge and before any CAMP product wave. It remains local-first: a trusted initiating OS user and controller are assumed.

## Goals / Non-Goals

**Goals:**

- Make every CAMP command source-controlled, immutable, independently digestible, and callable only by command id.
- Execute reviewed-head and exact-main proofs from new detached exact-SHA worktrees with a fixed Windows toolchain and sanitized environment.
- Bind each receipt to canonical repository/PR/review provenance, the exact child spec, exact product commit or merge, and writer-derived result facts.
- Publish only allowlisted, privacy-bounded artifacts into a durable store that remains valid after the proof worktree is removed.
- Make cleanup creation-bound, race-checked, non-force, and a prerequisite for the next wave.
- Preserve normal Playwright, UX-walkthrough, and viewport commands when no CAMP environment is present.

**Non-Goals:**

- General-purpose supply-chain attestation, hostile-local-user resistance, signing, or third-party non-repudiation.
- Authentication or ownership enforcement for local APIs.
- Campaign/custom-unit product behavior or PROOF-02 repair work.
- Caller-selected commands, arbitrary artifact ingestion, or raw reporter retention.
- New dependencies.

## Decisions

Canonical bytes are UTF-8 `JSON.stringify(commandSequence)`. `@node` and `@npm` are closed logical executable tokens: the controller expands them only to `[verifiedNodeExe,...args]` and `[verifiedNodeExe,verifiedNpmCli,...args]` absolute paths and never invokes PATH/CWD-selected binaries; every array is spawned separately with `shell:false`. Each `runRootTemplate` is a literal repo-relative path below `.sisyphus/evidence/playtest` with exactly one `<sha>` token. The resolver substitutes the expected 40-lowercase-hex receipt SHA and rejects any caller `--run-root` that is not byte-equal. `CAPTURE_CONTRACTS` is a separate frozen source-controlled registry whose only keys are PNG-retaining waves; each value maps a command-sequence index to one fixed invocation id and its exact sorted PNG paths, and absence means an exact empty capture set. Caller command text, other executable tokens, shell chaining, unknown/reordered/omitted/substituted arrays, root/capture-contract mismatch, or digest mismatch fails before staging, bootstrap, execution, export, or cleanup.

## Risks / Trade-offs

- **Large security-sensitive seam** -> Keep one schema, one immutable registry, one writer-owned receipt, mocked adapters for GitHub/Git/filesystem/process boundaries, and a strict 15-file/500-line implementation cap.
- **Local proof can be rewritten by a hostile local process** -> State the trusted-controller boundary; digests detect drift and substitution, not non-repudiation.
- **Exact toolchain can make other platforms unavailable** -> This wave supports the pinned Windows proof lane only; unsupported platforms fail explicitly.
- **GitHub or network unavailability blocks provenance** -> Publish no authoritative receipt and record the environment limit outside the receipt.
- **Evidence growth** -> Retain only allowlisted normalized facts and artifacts; never copy entire runner directories.
